## Findings

Part 1 (2026-11-19, PC, before the first release):

- **My calls.** Asked how a release goes in, I first picked a pull request that I merge. Asked next for my OK on a ruleset for `main` (no force pushes, no deletion, a pull request, merge commits only, no bypass), I said: "Actually, we don't need that many rules. This is a game jam project. Just merge into main." So GitHub gets no branch rules and there is no pull request: an agent merges `dev` into `main` on my word. That answer was also my word for the first release.
- **A release is a fast-forward, made with a push alone:** `git fetch origin`, then `git push origin origin/dev:refs/heads/main`. No working tree changes (the repo folder stays on `dev`), and git refuses the push if `main` ever holds a commit that `dev` lacks, since nobody force-pushes. It also keeps `main` an ancestor of `dev` for every later release. The other way, a merge commit (`--no-ff`), marks each release in `main`'s history, but `main` is then never an ancestor of `dev` again, and making it without checking out `main` needs `git commit-tree`. With no pull request, the fast-forward is simpler. So the version on itch.io is the released `dev` commit's (Done-when 4's "merge commit" assumed a pull request).
- **`main` before the release:** `d9cde1a`, the first setup, an ancestor of `dev` and 513 commits behind it. It had no protection: GitHub's public API says `"protected": false` for the branch, and its rules for `main` are `[]`. The repo is public and owned by a user account. This PC has no `gh`.
- **The menu.** `Tools/deploy_itch.py`: the default commit is `origin/main`; it fetches `main` and `dev`; its output says whether the commit it builds is `main`'s tip, and a real push of any other commit prints a note that the build is not a release. `Content/Python/nhos_itch_deploy.py`: the upload dialog names `main` and says how to ship newer work; "Build only (dry run)" is now "Build only (dry run of main)"; a new entry, "Dry run of dev", passes `--commit origin/dev --dry-run`; `launch()` takes a `commit`.
