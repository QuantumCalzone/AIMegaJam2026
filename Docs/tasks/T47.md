## Findings

### How the headpieces go on and off: no `BP_Show` change (my call, 2026-11-15)

The plan had one call in `BP_Show` (the PC's chain) at the scene's start and the sheet one in `BP_StageDirector.ResetStage` at Scene Prep (the PC's T62 held `BP_StageDirector` that day). I was offered a way with neither and took it:

- **`BP_Robot.WatchShow`**, called from `EventTick` (one line after `TickActs`), reads `BP_Show`'s `SceneNum` and `Phase` through a cached `ShowRef` (found with `GetActorOfClass`, as `BP_StageDirector.CardFromShow` finds the show). When `SceneNum` changes, that is a new Scene Prep: a standing robot takes its headpiece off (`SetHeadpiece("", "")`), a cut robot keeps its own, and a dress is due. The dress comes on the first tick where `Phase` is no longer `"scene prep"`, that is when the scene starts.
- **`SceneNum`, not `Phase` alone:** an autoplay show passes Scene Prep inside one frame (`SETUP`, `PREP shown` and `PREP start` all on frame 0), so a tick never sees `Phase` at `"scene prep"` there. The first build watched `Phase` only, and its first game-window show printed no `COSTUME` line at all.
- **`BP_Robot.DressFromShow`** finds the robot's seat (its index in `BP_Show.Robots`), that seat's dealt role (`BP_Show.SeatRole`, which `ScenePrep` fills by name with `SeatWant`), and the card in play (`CardId` in `CardArr`), then the card's seat with that role, and calls `SetHeadpiece(seat.headpiece, seat.color)`. A cut robot, or a seat with no role this scene, is left as it is.
- **What it costs:** `BP_Robot` now reads six `BP_Show` variables by name (`SceneNum`, `Phase`, `Robots`, `SeatRole`, `CardId` and `CardArr`), and holds a `BP_Show_C` reference (`ShowRef`), so `BP_Robot` and `BP_Show` reference each other (`BP_Show` already referenced `BP_Robot`). A task that renames one of them, or deals roles some other way, must update `DressFromShow` or `WatchShow`. Nothing in `BP_Show`, `WBP_Stage` or `BP_StageDirector` changed, so T47 has no part left for the PC.
- **Why not the two hooks I first described** (dress in `BP_Robot.Setup`, undress in `GoHome`): `BP_Show.StageSetup`, which calls `Setup` on every robot, runs only once a show, at scene 1's start (one `NHOS: STAGE robots=5` per show in T80's log), so later scenes would never dress. And `GoHome` taking the hat off would have been a side effect for any later caller.

### Unreal MCP and editor rules found in this task

- **Reading `BP_Show`'s graphs marks it dirty.** After `read_graph_dsl` on `StageSetup` and `ScenePrep` (and `find_nodes`, `get_node_infos` on others), `BP_Show` showed as an unsaved change. `EditorLoadingAndSavingUtils.reload_packages` on it (the disk version was the one the editor had) cleared it. Check the dirty list after reading a Blueprint you must not save.
- **`get_node_type_pins` makes temporary nodes** in the graph you name (their refPaths come back); they were gone afterwards, but name your own new graph there, not someone else's.
- **`Game|AddComponentbyClass` takes only `self` and `Class` in the DSL**: no `bManualAttachment` pin. Attach the new component afterwards with `AttachComponentToComponent`.
- **`write_graph_dsl` returns typed outputs only if the function has them**: add output params with `add_function_param` (`input_param: false`) and compile before the write, as for inputs.
- **The relative-location getter is `Class|SceneComponent|GetRelativeLocation`** (and `GetRelativeScale3D`), not `Transformation|...`.
- **A bind of a pure node reads its inputs when it is used, not when it is bound**, so keep an old value in a variable before you set the variable it reads (`WatchShow`'s first build).
- **An autoplay show passes Scene Prep inside one frame**: anything that polls `Phase` from a tick never sees `"scene prep"` there.
- **The Mac editor's log** is `~/Library/Logs/Unreal Engine/AIMegaJam2026Editor/AIMegaJam2026.log`, not `Saved/Logs/`.
- **Simulate-in-Editor** (`StartPIE` with `bSimulate`) gives a play world without the title screen, where editor Python can call Blueprint functions on the robots (`unreal.UnrealEditorSubsystem().get_game_world()`, then `call_method`) and `CaptureViewport` films it from any pose. A capture can still miss a part (T80's finding): capture again before you judge.
