## Task

- **Why:** my request on 2026-11-15: the director's note clue always shows the note's category. It should rotate, so the next scene gives another kind of clue, for example only the vowels of the note. T50 put the category on my card ("Note category: Props" over "Note: ██████ (bots only)") and in every AI's state as `scene_card.note_category`. I picked these twelve kinds from a list of 22. I chose one task, not two, so it runs longer than an hour. The examples all use the note "Never move to the Back.":

  | Id | Card label | The example shows | Comes from |
  |---|---|---|---|
  | `category` | Category | Movement | the note's `category` |
  | `vowels` | Vowels only | `_e_e_ _o_e _o __e _a__.` | built from the note |
  | `first_letters` | First letters | `N… m… t… t… B….` | built |
  | `consonants` | Consonants only | `N_v_r m_v_ t_ th_ B_ck.` | built |
  | `scrambled` | Scrambled words | `veNre vemo ot hte cBak.` | built, new each show |
  | `pig_latin` | Pig Latin | `Evernay ovemay otay ethay Ackbay.` | built |
  | `key_blank` | Key word hidden | `Never move to the ████.` | built, from the note's new `key` |
  | `key_only` | Only the key word | `█████ ████ ██ ███ Back.` | built, from `key` |
  | `emoji` | Emoji | 🚫🚶🔙 | written for each note |
  | `opposite` | Opposite day | `Opposite of: Always move to the Back.` | written |
  | `riddle` | Director's riddle | `Some corners of my stage are cursed.` | written |
  | `autocorrect` | Autocorrect | `Never moose to the Bach.` | written |

- **Steps:**

Then write the rule in the design doc: the Rules tab ("Scene Prep", "The Scene & acting", "Free Talk" and the card row of the onboarding table) and the Bot Prompts tab (the note lines that T50 copied into `prompts.json` `game`, word for word: "Every actor sees the director's note category…" and "Fitting the category is not proof…"). The bots must know which kind of clue I got and its exact text, so that they judge my first turn by what I could know. Show me the edit before you save it.
  2. **The data.**
     - Add `Content/NHOS/Data/clues.json`, with one entry per kind. Each entry has:
       - `id` (from the table)
       - `label` (the card's name for the kind)
       - `how` (one line that tells the bots how the clue was made, for example "the note with every letter except a, e, i, o and u blanked")
       - `from` (`built`, or the `scenes.json` field that holds the clue)
       - whether the kind may come in scene 1 (from my answer in step 1)
     - In `scenes.json`, give each of the 10 notes these five new fields. Show me all 50 before you go on.
       - `key`: one word of the note, written as it is in the note. A first pick: Back, Center, hold, give, Throw, Riser, different, looking, favorite, question.
       - `emoji`: 2 to 4 emoji.
       - `opposite`: the reverse rule, no longer than the note.
       - `riddle`: at most 10 words, in the director's voice, without the key word.
       - `autocorrect`: the note with two or three words changed to near-spellings. It must still be readable.
  3. **The emoji check.** Before you write the emoji, put a few on my card in PIE and take a screenshot. If the UI font does not draw them, ask me which fallback to use:
     - the monochrome Noto Emoji font (SIL OFL) as a sub-font of the UI font for the emoji ranges, or
     - a small icon set shown as images: Twemoji (CC BY 4.0) or OpenMoji (CC BY-SA 4.0).

     Record the source and license in `Docs/Assets.md`. If a new kind of binary file comes in, add an LFS rule for it before you commit.
  4. **The builder.** Make a new component, `BPC_NoteClue` on `BP_Show`, and call it from one node in `ScenePrep`.
     - `Draw` picks at random a kind that this show has not used yet. A show has at most 4 scenes, so no kind repeats.
     - `Build(Kind, Note)` returns the clue's text. The rules for the built kinds:
       - `vowels`: every letter except a, e, i, o and u (in either case) becomes `_`. Spaces and punctuation stay.
       - `consonants`: a, e, i, o and u become `_`.
       - `first_letters`: the first letter of each word, then `…`. The end punctuation stays.
       - `scrambled`: each word's letters are shuffled in place, and its punctuation stays. If a word with two or more different letters comes out unchanged, shuffle it again.
       - `pig_latin`: a word that starts with consonants moves them to its end and adds "ay". A word that starts with a vowel adds "yay". A capital stays on the first letter, and punctuation stays at the end.
       - `key_blank`: the key word becomes one `█` per letter.
       - `key_only`: every word except the key word becomes one `█` per letter.
       - `category` and the four written kinds: the note's field. The card puts "Opposite of: " before the opposite.
     - Add two switches to `Local/switches.json`, and describe both in `Docs/switches.example.json`'s `_readme`:
       - `clue` forces one kind, by its id.
       - `clue_test: true` logs every kind for every note when the show loads (`NHOS: CLUETEST <note id> <kind> <text>`), so the rules can be checked from the log with no show.
  5. **The deal and the state in `BP_Show`.**
