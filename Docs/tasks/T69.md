## Task

- **Why:** I want to know what players try to do that the game doesn't support, to see which verbs, props or places to add next. [T67.md](T67.md) has the rest of the why. Before T63 the input LLM quietly turned an action it couldn't do into a look ("inspect the crown jewels" became look at Prop Table) and left no trace. After T63 the builder offers only valid actions, and typed text never controls an action. So players now show what they want in two places: the stage directions they type into the speech field anyway ("*does a backflip*", "I jump on the table"), and the greyed-out actions they click (Throw while holding nothing).
- **Steps:**
  1. **The input ask flags stage directions.** T63's input ask only fixes spelling. Give its reply a short field (name it in the prompt, such as `attempt`) that names, in at most 6 words, a physical action the typed line describes or asks for ("backflip", "climb the chandelier"), and is `""` when the line is only speech. The field never changes the line or the turn: the line is still sent as typed and fixed, and the action is still the one the builder built.
     - The reply schema is shared by every ask, and strict mode makes every field required. So either every ask returns the new field empty, or the input ask gets its own schema. Weigh the token cost and the four providers' strict-schema rules, and write the pick under "## Findings".
     - `Tools/check_prompts.py` checks the new field. Free mode leaves it empty.
  2. **Send it.** When the field is not empty, `BPC_Analytics.Send` an `unsupported` event: `words` (the field, cut to 6 words), `source` `typed`, `phase`. Only those few words are stored, never the typed line: the line is the player's own writing.
  3. **The builder's blocked clicks.** If `WBP_ActionBuilder` (T64) can tell a click on a greyed-out action or chip, send `unsupported` with `words` (the verb and why it's blocked, such as "throw, holding nothing"), `source` `builder`, `phase`. At most once per verb per turn. If T64's widget can't tell those clicks apart without a rework, leave it and say so under "## Findings".
  4. **The design doc.** Propose the Bot Prompts tab's edit for the input LLM's new field, and wait for my OK before you make it.

## Findings

**Steps 1 and 2, pushed on 2026-11-16 (PC, editor on port 8000), with the builder's hook still to do.** Built from [T69-build.md](T69-build.md) parts 1 to 4 and 5d, re-checked first against `b95b624` (T68 checked): every graph source, anchor and data line the sheet names was as it says.

**The schema (decision 1): the input ask has its own, `input_schema`.** It is a new top-level key in `Content/NHOS/Data/llm.json`, right after `reply_schema`: `reply_schema`'s properties exactly (T60's `tell` with its enum included), plus `"attempt": {"type": "string"}`, with `attempt` added to `required` and `additionalProperties` false. `reply_schema` doesn't change, so no actor reply carries `attempt` and no actor prompt mentions it. `BPC_LLMClient.BuildBody` sends `input_schema` when `Role` is `input` (through `BSchema`), and `LoadConfig` falls back to `reply_schema` if the key is missing. The checker's `request_body` does the same, and `check_files` fails if `input_schema`'s properties aren't `reply_schema`'s plus `attempt`, if its `required` isn't `reply_schema`'s plus `attempt`, or if `reply_schema` gets `attempt`. **For T76:** add `emotion` to both schemas; the check fails if only one has it.
- **Why its own schema, not a shared field:** strict mode on all four providers (Anthropic's structured outputs, and `strict: true` on the three `openai_chat` providers) makes every property required. A shared field would make every actor reply on every provider return `"attempt": ""`: about 135 calls a show, each writing about 5 more output tokens and sending a bigger schema, for a field actors must never fill. A field named `attempt` in the actors' schema would also invite them to write stage directions into it, and their prompts would need a line against it. Its own schema costs one key in `llm.json` and two small edits (`LoadConfig`, `BuildBody`). T60's `tell` is shared because actors fill it; `attempt` is filled only by the input LLM.
- **No `maxLength`** on `attempt`, so the schema stays valid if `roles.input` ever moves to an OpenAI-shaped provider. `BPC_Analytics.Unsupported` cuts to 6 words and 80 characters.
