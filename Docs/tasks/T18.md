## Findings

### T18: one LLM per AI player, in the game (2026-11-14)

- **Three modes,** picked on the title screen (`WBP_Title`: Test for Free, Play via Relay, Play with my own API keys) or, for autoplay runs, by `"mode"` in `Local/switches.json` (`free`, `relay`, `keys`; a missing or unknown mode means `free`). `BPC_LLMClient.SetMode` checks the choice: relay needs the relay address, keys needs keys for at least 3 of the 4 providers. `NHOS: MODE <mode>` and `NHOS: CLIENT ready mode=<mode> keys=<n>` print it.
- **Test for Free makes no network call.** `Ask` queues the ask and a 0.3 s timer (`FlushLocal`) answers it with `FreeReply`, a Blueprint copy of the relay's `freeReplyObject`: it finds the phase in `free_mode.json` (a state field, or words in `ask`), fills `{actor}`, `{place}`, `{prop}` and `{vote}`, picks a vote from `options` that isn't the asker, adds weighted stage actions, and repeats the typed text (25 words at most) for the input step. Replies come back later, not inside `Ask`, so the show loop sees the same timing as a real call. `Replace` fills every copy of a placeholder with the same pick (the relay picks again for each).
- **Routing.** An actor ask goes to its persona's provider, read from the tag (`<persona id>-<n>`, the form every actor ask in `BP_Show` already uses), so no ask in `BP_Show` changed. Input and Director asks use their role's provider (Anthropic); in key mode without an Anthropic key they use the first provider that has one, with that provider's model. `BuildBody` builds the Messages body or the Chat Completions body from `llm.json` `providers`. `SendReq` sends it: to the relay as `{provider, session, body}` (one session id per show, made in `StartShowSession`), or straight to the provider with its own headers (`x-api-key` and `anthropic-version`, or `Authorization: Bearer`). `ParseReply` reads both reply shapes: for chat, `choices[0].message.content`, `finish_reason` `length` or `content_filter`, a `refusal`, or an `error` object.
- **Every `NHOS: LLM` line ends with `provider=<id> mode=<mode>`.**
- **Seat draw.** New `BP_Show.DrawCast` runs first in `SetupShow` (a call node and a Branch put in by hand, not a DSL rewrite of `SetupShow`). It keeps the full persona list in `AllPersonas`, keeps only personas whose provider can take a seat (`CanSeat`: any provider in free and relay mode, a provider with a key in key mode), prints `NHOS: DRAW ai=<n> providers=<ids left out>`, and calls `SetUnavailable` when fewer than 3 AI seats are left. In key mode, `StartShowSession` names the missing providers, for example: "Play with my own API keys needs keys for at least 3 of the 4 AI providers. Missing: OpenAI, SpaceXAI, Meta."
- **Keys screen** (`WBP_Keys`): one masked field per provider, filled from `Local/llm_key.json` when it exists. Save and Play calls `SetKey` for each field, `SaveKeys` (writes the file with `Json|SaveJsontoFile`, prints `NHOS: KEYS saved=<bool> count=<n>`, never a key) and `SetMode keys`, then starts the show. With fewer than 3 keys it shows the message from `SetMode` instead. Back closes the screen. Not clicked by hand yet (computer use can't reach the editor, which isn't installed through the Start menu); the layout was checked in the designer (`Saved/T18/shots/keys_designer.png`, not in git).
- **One retry.** A failed ask (transport, provider error, `finish_reason`, a reply that isn't JSON) is sent again once and prints `NHOS: LLM <tag> retry <reason>`. Limits, budget, `bad_request` and refusals aren't retried. Why: the first relay show had two `gpt-6-luna` asks fail with `finish_reason length` after about 13 s, so the model ran to the 2000-token cap; the 87 OpenAI asks in T16 had none. The failure message now adds `out=<tokens> chars=<n> starts=<first 120 characters>` to find the cause if it happens again. The retry path hasn't run yet: the next relay show had no failure.
- **PIE runs** (autoplay, `spare_human`): free mode 87 asks, `SHOW END result=win scenes=3`; relay show 1, `SHOW END` with the two OpenAI failures above (before the retry); relay show 2, 88 asks, no `fail` or `retry`, `SHOW END`; free mode with the relay address set to `https://no-such-relay.invalid`, 88 asks and no `LogHttp` line; key mode with only my Anthropic key, `NHOS: SHOW UNAVAILABLE` with the missing providers. No `LogScript` line in any run. The two relay shows cost about $0.22. `check_prompts.py --log` on relay show 2: 66 of 68 AI lines legible; the two failures quote a famous line from a parodied film (a prompt matter, not T18's).
- **Not checked:** the direct-call path with real keys (only my Anthropic key is in `Local/llm_key.json`, so key mode can't seat a cast here), and a full set of 4 keys with one removed.
- **Unreal MCP:** a function's call nodes go stale when it gets a new parameter, and a stale node blocks every compile; delete them (`find_nodes` by title, `delete_node`) before writing. The DSL's `MakeArray` takes one input; build longer arrays with `Add`. `Map Clear` won't connect to the HttpBlueprint headers variable, which is an `HttpHeader` struct, not a map: reset it by setting it from an empty `HttpHeader` variable. `get_node_type_pins` doesn't leave nodes behind. Read-backs name some calls after another class with the same function name (`Class|BPRobot|Setup` is `BPC_LLMRequest.Setup`, `Class|PCGSelectGrammarSettings|SetKey` is `BPC_LLMClient.SetKey`); the nodes are right.
