## Task

- **Model and effort:** Sonnet 5.5, medium. Picking loops from a pack we own, a key map in the component T20 built, and two keys in `RunCue`.
- **Depends on:** T20 (`BPC_ShowAudio`)
- **Needs:** the Kenney bundle on the Windows PC (`Local/audio/kenney/`), editor + Unreal MCP running, my OK before any paid music tool. Picking the tracks (steps 1 and 2) needs no editor and can run as prep.

- **Steps:**
  1. **The track list.** One loop for each item below, and no loop used twice:

  2. **Find the tracks.** This step needs no editor.

     - If no Kenney loop fits a card, use another free library whose license allows a game (CC0 or CC BY), or an AI music tool whose terms allow game use. Get my OK before anything that costs money.

Don't read asset paths from a JSON file: the cook packs only the assets that something references, so a track named only in JSON would be missing from a packaged build. A card with no track plays the old show loop, so a new card still has music. A phase with no track keeps the loop that is playing, so a phase added later (T58's last word, between Free Talk and The Cut) goes on with the Free Talk loop. `NHOS: SOUND music <key>` prints as it does now.
  5. **The show asks for the right key.**

     - Take both from what the cue carries, not from the live `Phase` variable on `BP_Show`: the show's logic runs ahead of the line queue (T30).
     - Check that `CardId` already holds the new card when the `prep` cue plays. If `ScenePrep` sets it, ask for the music after `ScenePrep`.

  6. **A short fade between tracks** (about 1 s), if it can be done. ## Findings

### What was built

- **`BPC_ShowAudio`** (all sources in `Graphs/BPC_ShowAudio/`):
  - `TrackFor(Key)` maps each key to its sound with an `if` chain, so each track is referenced by the Blueprint and the cook packs it. It has 12 keys and 12 different tracks; any other key gets `S_MusicShow`. An asset path works as a literal on a function's `SoundBase` return pin.
  - `PhaseKey(Text)` turns a header into a key: `SCENE PREP` and `THE SCENE` give `card`, `FREE TALK` gives `free_talk`, and `THE CUT` gives `cut`. Any other header gives "", and the loop that plays goes on.
  - `PlayPhase(Text, CardId)` is the one call that `RunCue`'s `phase` cue makes.
  - `StopMusic` and `DuckMusic` are new. `EndMusic` runs on a 3 s timer from `EndCheer`, and only if no other music started first.
  - `SwapMusic`, `StartDrum`, `Reveal` and `EndCheer` were rewritten. `Reveal` isn't in the Touches line, but it needed one node so that nothing plays under the stinger.
  - A new Boolean variable, `EndWin`.
- **`BP_Show`:**
  - `RunCue`: the `phase` cue calls `PlayPhase`, the `tie` cue stops the music with the drum, and the `prep` cue no longer plays music itself. T57's `passed` and `unpass` cues are kept.
  - `OpenPrep` (not in the Touches line): one node starts the card's loop there.
  - **Why `OpenPrep`:** `ShowPrep` sets the Scene Prep header straight on the stage (`WBP_Stage.SetPhase`), not through a `phase` cue, so no cue carries `SCENE PREP`. Scene 1 has no `prep` cue either: `SetupShow` calls `ScenePrep` directly. With the sheet's plan, the title loop would have played under scene 1's Scene Prep. `ScenePrep` sets `CardId` before it calls `ShowPrep` and `OpenPrep`, and `CardId` is set nowhere else. So `OpenPrep` asks for the right card at every Scene Prep, and always at the queue's pace.
- **The fades** (step 6) work. `create_node` with `declaring_class` `/Script/Engine.AudioComponent` makes the Audio Component's `FadeOut`, `FadeIn` and `AdjustVolume`, and `connect_pins` wires them:
  - `StopMusic`: `FadeOut`, 1.0 s to 0.0, in place of `StopDelayed`.
  - `SwapMusic`: `FadeIn`, 1.0 s to 1.0, after `Set Music`. Its `self` comes from `Set Music`'s output. `SpawnSound2D` is kept.
  - `DuckMusic`: `AdjustVolume`, 1.0 s to 0.4, after the print.
  - Each of the three source files says so in its first lines, so that a rewrite from the file redoes the splice.
- **The Cut loop plays only about 1 ms before the drum** (`SOUND music cut` and then `SOUND duck` / `SOUND drum`, in the same frame), so the duck stays, as the sheet planned.

### Unreal MCP rules found in this task

- **The editor's auto-import picked up the runtime JSON files on this PC.**
  - What happened: the 11 copied `.ogg` files brought up the editor's "N changes to source content files have been detected" note, with 19 changes. Pressing Import also started a DataTable import of `Content/NHOS/Data/prompts.json`. Its modal "DataTable Options" window blocked the editor and every MCP call until my person pressed Cancel. No DataTable was made.
  - The cause: the local `Saved/Config/WindowsEditor/EditorPerProjectUserSettings.ini` has its own `AutoReimportDirectorySettings` that skips only `Localization/*`. It overrides the project file's entry, which also skips `NHOS/Data/*` (commit `891f0b3` warned about this).
  - The fix that worked: set `AutoReimportDirectorySettings` on `/Script/UnrealEd.Default__EditorLoadingSavingSettings` with `set_properties` to the project's value (wildcards `Localization/*` and `NHOS/Data/*`, both `bInclude` false), then delete the copies and copy them again. The editor then logged `AssetReimport: Importing new asset ...` for the 11 files only, without a prompt.
  - Do that before any auto-import on this PC. The in-memory value stays until the editor closes.
- **Setting `bPromptBeforeAutoImporting` to false in memory didn't stop the note.** The note still came, possibly because it reports changes found when the editor started. The Slate inspector's `Click` on its Import button only focused the button; `PressKey` `Enter` then pressed it. Both settings were set back to true afterwards, as T72 did.
- **`AssetTools.read_file` reads only `.csv`, `.html`, `.json`, `.md`, `.py` and `.txt` files, under `/Game/` or `Saved/`.** Write a graph's expanded DSL to `Saved/<task>/<Graph>.txt`, read it inside `execute_tool_script`, and pass it to `write_graph_dsl`. Then no long DSL needs to be pasted into a tool call.
- **`Tools/dslpp.py` writes nothing for a file without a `;;; GRAPH <Name>` line.** The `Graphs/` files have none, so put that line in front before you expand a file.
- **`write_graph_dsl` leaves the graph's old nodes behind, cut off from the entry.** `SwapMusic` still holds T20's old chain, which never runs. This is the same thing T50 found in `ActorState`. The chain compiles cleanly with `warnings_as_errors`, so it is harmless.
- **The Audio Component's `FadeOut`, `FadeIn` and `AdjustVolume` come from `create_node`** with `declaring_class` `/Script/Engine.AudioComponent`. `Variables|Default|GetMusic` makes a getter with no declaring class. A variable setter's `Output_Get` pin can feed `self`.
