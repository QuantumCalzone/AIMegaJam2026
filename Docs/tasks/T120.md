## Task

- **Why:** T92 found it on 2026-11-20. The game writes two files into `Local/` under `Get Project Directory`: the key screen's `llm_key.json` (`BPC_LLMClient.SaveKeys`) and the stagehand's first-show flag `progress.json` (`BPC_Stagehand.SetTipsNext`, read by `TipsNext`). In the Mac build, that folder is inside the app bundle (`AIMegaJam2026.app/Contents/UE/AIMegaJam2026/Local/`). A player's download is quarantined, and until the player moves the app in Finder, macOS runs it from a randomized read-only copy (App Translocation: T92's log shows the game's base directory under `/private/var/folders/.../AppTranslocation/.../d/AIMegaJam2026.app`). The app is also sandboxed, which may block writes into its bundle even after a move. Writing into the bundle would also break its signature. So on a Mac, a player who plays with their own keys has to paste them again at every launch, and the stagehand's first-show tips may come back at every show. Play doesn't break: the key screen goes on to the key test when `SaveKeys` fails. On Windows, and in the editor, `Local/` next to the game is writable, and nothing there changes.
- **Steps:**
  1. **Look.** Read T92's findings ("Found on the way") and T61's (the stagehand's `progress.json`), and the graph sources `Graphs/BPC_LLMClient/LoadConfig.txt`, `SaveKeys.txt`, `Graphs/BPC_Stagehand/TipsNext.txt` and `SetTipsNext.txt`. Note how `BPC_Analytics` keeps its player id (the `SG_Player` save game, `Graphs/BPC_Analytics/LoadSave.txt`); save games land in the app's container, which the sandbox allows.
  2. **Pick the folder.** In a packaged Mac build, write and read `llm_key.json` and `progress.json` in a folder the sandbox allows, such as `Local/` under `Get Project Saved Directory` (inside `~/Library/Containers/com.YourCompany.AIMegaJam2026/Data/`). Keep `Local/` under `Get Project Directory` everywhere else, so Windows builds, the editor and `CLAUDE.md`'s `Local/` row stay as they are. Keep reading `switches.json` from the bundle's `Local/` too, because T92's test recipe writes it there. Find out what `Get Project Saved Directory` gives in the sandboxed app, from its log, before you rely on it. If a save game is the better place for the flag, say why and use it.
  3. **Build it.** One small function that returns the folder for these files (in `BPC_LLMClient`, or a new component that `BPC_Stagehand` can call too), used by `LoadConfig`, `SaveKeys`, `TipsNext` and `SetTipsNext`. Print where it saves (`NHOS: KEYS saved=... path=`). Keep `Graphs/` in step, and run `python Tools/check_prompts.py --offline` before you push a graph.
  4. **Check on Windows and in the editor:** PIE saves and reads `Local/` in the repo folder as before.
  5. **Check on the Mac.** Package (Tools > itch.io > "Dry run of dev" after the push builds `dev`'s tip in the deploy worktree). On a copy of the app with the quarantine flag that a download has (`xattr -w com.apple.quarantine ...` copied from a real download), opened once with my Open Anyway so that macOS translocates it: paste a test key on the key screen, quit, open it again, and the key screen shows the key saved; play a show with tips on, and the next show has no first-show tips. The app still passes `codesign --verify --deep --strict` afterwards, because nothing was written into the bundle. Delete the copy, and the files it wrote in its container.
  6. **The docs.** "Package a macOS build" and "The Mac file is the pushed folder" in `Docs/Builds.md` (where a Mac build keeps the keys and the flag, and that the secrets check never sees them, since they are outside the build), and "Where your keys go" in `Docs/ItchPage.md`.
- **Done when:** on the Mac, a translocated copy of the packaged app keeps a pasted key and the first-show flag across a restart, and still passes `codesign --verify --deep --strict`; on Windows and in the editor, both files are in `Local/` as before; a free autoplay show reaches `NHOS: SHOW END` in PIE and in the Mac build; no key is in git or in the chat.
