- **Depends on:** nothing open. The relay path (T18) and the screen's layout (T27) are done.
- **Needs:** editor + Unreal MCP running, Test for Free for the PIE checks, and one relay show (about $0.11 on my keys, so my OK first). - **Why:** my request on 2026-11-14. Every ask that goes through the relay spends my money, and I want to see it go. A burning bill in the corner says "that cost me", as a joke.
- **Steps:**
  1. **A widget of its own, `WBP_MoneyBurn`** (new, in `Content/NHOS/UI/`; `WBP_Stage` and `BP_Show` stay untouched). A full-screen overlay that holds one slot at the bottom right, the same distance from the window edge as the chat panel's gap on the left. It is not hit-testable and not focusable, so it never takes a click or the input box's focus, and its Z-order is above `WBP_Stage`. A function `Burn` adds one burning bill to the slot: it shows at once, burns for about 1.4 s (the bill blackens from one edge, the flame flickers, a few embers rise) and fades out. A scene turn sends five or six asks at once, so each bill gets a small random offset and tilt, up to 6 show at a time, and a seventh replaces the oldest. Each bill removes itself when it is done.
  2. **The art:** one banknote and a flame in the theater's look, as a flame flipbook (6 to 8 frames) or an animated flame material, played in UMG. Take it from an AI image tool or a free sprite sheet whose license allows use in a game. Record what it is, where it came from (the tool and prompt, or the link) and its license in `Docs/Assets.md`. Import it next to the widget under `Content/NHOS/UI/`, and check that `.gitattributes` stores its file type in LFS.
  3. **The hook.** `BPC_LLMClient` calls `Burn` once for each reply that the relay sends back with status 200, because by then the provider has spent tokens. It is one node where `HandleHttp` reads a relay reply, and it sits on that graph as T21 leaves it (start from the pushed `Graphs/BPC_LLMClient/HandleHttp.txt`). A retry is a new call, so it burns again. Nothing burns in Test for Free or key mode (those cost me nothing), for a relay error reply (`session_limit`, `player_limit`, `budget_used_up`, or a failed call), or for T21's `GET /health`. `BPC_LLMClient` creates the widget once, the first time it needs it, and adds it to the viewport. Print `NHOS: BURN <tag>` for each burn.
  4. **A test switch, so the look checks cost nothing.** `"burn_test": true` in `Local/switches.json` makes Test for Free call `Burn` for every ask too, as if it went through the relay. Add it to `Docs/switches.example.json`. Set it back to `false` before a person plays.

## Findings

### T35: the money burn (2026-11-15)

Built on the Windows PC through Unreal MCP, checked in PIE (floating windows at 1600 × 900 and 1280 × 720, Test for Free) and in a game window (the relay show).

- **Two new widgets, nothing in `WBP_Stage` or `BP_Show`.**
  - `WBP_MoneyBurn` is the overlay: a full-screen canvas, `HitTestInvisible`, with one `BillSlot` canvas (220 × 140) anchored to the bottom-right corner, 24 px from both edges, the same gap the chat panel keeps on the left. `BPC_LLMClient` adds it to the viewport at Z-order 10: above `WBP_Stage` (0), below the title (20), the key screen (30) and the unavailable screen (40, 50). Its `Burn` function adds one `WBP_BurningBill` at a random offset (x 20 to 70, y 0 to 30 inside the slot) and tilt (±10°). Up to 6 burn at once; a seventh removes the oldest.
  - `WBP_BurningBill` is one bill, 150 × 110, animated on its own tick (no UMG animation asset). Over 1.4 s, with an ease-in-out, a clipping canvas holding `T_BillChar` grows from the left edge over `T_Bill`, so the bill blackens from one edge. An 88 × 88 flame rides that edge: `T_FlameSheet` (704 × 88) slides inside a clipping canvas, one 88 px frame at a time, at 14 fps. Four embers rise and fade near the flame. From 1.4 s the whole bill fades, and at 1.8 s it removes itself.
  - `Burn` drops bills older than 1.9 s from its list by their start time (`Get Real Time Seconds`) instead of an `IsValid` check, because `Utilities|IsValid` names three different nodes in the DSL.
- **The hook.** `BPC_LLMClient.Burn(Tag)` prints `NHOS: BURN <tag>`, creates the overlay the first time (a `BurnMade` flag), and calls its `Burn`. `HandleHttp` calls a new `BurnPaid(Tag, ParseOk, ParseErr)` right after `ParseReply`. It burns only in relay mode, and only when the relay passed a provider reply through: `ParseReply` succeeded, or it failed with no error type on a body that was JSON (`stop_reason` `max_tokens` or `refusal`, or fields that don't parse). The relay wraps every non-200 answer (`session_limit`, `player_limit`, `budget_used_up`, `provider_error`) in `{"type":"error"}`, so those never burn. A retry is a new call and burns again. `/health` and the key tests return before that point, and a reply that comes back after the relay went down is dropped without a burn. Free mode and key mode never burn.
- **`burn_test`.** `LoadConfig` reads `"burn_test"` from `Local/switches.json`, and `NHOS: CLIENT ready` now ends with `burn_test=<true|false>`. With it on, `FlushLocal` calls `Burn` for every free ask, just before `Deliver`.
- **Checks.**
  - Free autoplay with `burn_test` on: 88 `NHOS: BURN` lines and 88 `NHOS: LLM ... ok` lines, the same tags in the same order (1600 × 900); again 89 and 89 (1280 × 720). Both shows reached `NHOS: SHOW END` with no `LogScript` warning.
  - Free autoplay with `burn_test` off: no `NHOS: BURN` line, 88 `ok` lines, `SHOW END`.
  - Screenshots (in `Saved/T35/`, not in git) at 1600 × 900 (a scene turn, Free Talk, the vote row) and 1280 × 720 (Free Talk) show the bills at the bottom right, clear of the chat panel, the vote row, the info card and every robot's label. In a hand-played show, text typed into the input box while a turn's bills burned went in (`h7.png`). After a submit, the box kept keyboard focus and its caret while the next turn's bills spawned.
  - Relay autoplay in a game window (about $0.11): 89 `NHOS: BURN` lines for 89 relay replies, the same tags in the same order, no fail or retry, `SHOW END result=win scenes=3`.
- **Art.** Imported from `Docs/MoneyBurnArt/` into `Content/NHOS/UI/MoneyBurn/` as `T_Bill`, `T_BillChar`, `T_FlameSheet` and `T_Ember` (UI texture group, no mipmaps, `TC_EditorIcon` compression so the colors stay exact). `Docs/Assets.md` lists each one with its source and license. `.gitattributes` already sends `*.png` and `*.uasset` to LFS.
- **Unreal MCP rules found in this task:**
  - **`TextureTools.import_file` imports a PNG as a Texture2D.** T14's "MCP can't import a file" still holds for fonts.
  - **Slate screenshots come back as base64.** `AssetTools.write_file` writes them only under `Saved/` and only with a text extension (`.txt`, `.json`, ...), so save the base64 as `.txt` and decode it outside the editor.
  - **An `execute_tool_script` runs on the game thread, and no frame passes while it runs.** To catch something a frame or two after an action (a bill right after a submit), end the script, wait about half a second outside it, and screenshot in a second script.
  - **The editor throttles to about 3 fps when it isn't the foreground app**, and PIE in a floating window with it. `EditorPerformanceSettings.bThrottleCPUWhenNotForeground` turns that off; I set it back to `true` afterwards.
  - **`SlateInspectorToolset.PressKey` sends key events, not characters.** Enter submits, but letters never reach a text box. Use `Type`, which also focuses the box first.
  - **`BlueprintTools.compile_blueprint` returns null whether or not it worked.** `UMGToolSet.CompileWidgetBlueprint` returns true or false for widgets; for others, read `LogBlueprint` in the editor log.
  - **Widget property names in `ObjectTools.set_properties` are the camelCase names from `list_properties`** (`brush`, `layoutData`, `renderOpacity`, `visibility`, `clipping`). A canvas slot's size is `layoutData.offsets.right` and `.bottom` when its anchors are a point.
