## Task

- **Why:** my request on 2026-11-18: fix the bugs T87 found while it played its shows (three in PIE by hand, four free autoplay shows in a game window). T87 fixed the two that were in its own way (T77's `StageLine`, which had stopped every line's action from playing, and the same trap in its own `RiseAll`); these five are left. Each was seen in T87's logs or screenshots; "## Findings" in [T87.md](T87.md) has the details.
  1. **Banners fall behind the lines.** `WBP_Stage` keeps its own banner queue: `NextBanner` shows each banner for 3.5 s, then `FadeBanner` fades it over 0.5 s, so each banner takes 4 s. The line queue waits only `cue_hold.banner` (2.0 s, `pacing.json`) after a banner cue. So banners in a row fall further and further behind. On a win, the screen still showed "The cast gives one last verdict..." under the new header THE REVEAL as the first reaction started, and "The cast learns the truth." showed only during the first line. T52 saw a tie make four banners in a row (T34-build, row 15). T34-build's 2.6 plans to make the hold longer (`UITime "Banner"`, 4 s, and longer for long lines), which would widen the gap.
  2. **A robot at the Back mark hides behind the robot standing at the middle home spot.** In two of T87's PIE shows, a robot that had moved to Back in scene 3 stood straight behind OpenAI's home, so the camera showed only its label: in one show it was SpaceXAI, cut there; in the other, Anthropic, which then reacted unseen. T87 sends every robot home at the reveal, so the reveal is fine now, but during the scenes it still happens. T19 meant to prevent it: `BP_StageDirector.PickSpot` counts a spot as taken when another robot's goal is within 95 cm sideways and 140 cm in depth "because a robot one step behind another hides it from the camera". The likely cause is that the Back row sits more than 140 cm behind the home row, but the camera still lines them up; OpenAI also hovers (T79), so it is taller.
  3. **`fast_lines` is read only once.** `BPC_LinePlayer.LoadPacing` reads it the first time a line or cue is queued, but `Docs/switches.example.json`'s `_readme` says the game reads the switches "at the start of each scene and each Cut". T87 turned it off mid-show to get normal-pace screenshots of the reveal, and nothing changed.
  4. **Free mode can give two robots the same line in one round.** `BPC_LLMClient.FreeReply` draws each reply's line at random, on its own, so in T87's first autoplay show two robots said "Wait. The human was here the whole time? I need a reboot." in one reveal. It only happens in Test for Free and the relay's free mode, but Test for Free is a player's first look.
  5. **Nothing guards against the DSL trap that broke `StageLine`.** In `write_graph_dsl`, when an `if` body ends in a branching node such as `Utilities|IsValid` and code follows the `if`, that code becomes the `if`'s else path. T77's `StageLine` was written that way, and the stage director call never ran from T77 to T87. T87 scanned every `Graphs/` source and found no other case, but the next graph written that way breaks silently.
