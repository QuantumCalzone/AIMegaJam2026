## Findings

### Decisions (mine, in my person's place)

1. **Import: the prep's GLBs through Interchange.** Each comes in at x100 (metres to cm), +Z up, and facing mesh **+Y**, so yaw 270 turns it to the Rig's +X, as T82's FBX did. Mesh +X is the model's left, so after the yaw it is the Rig's -Y, the robot's left. The importer marks the normal map (OpenGL, flip green) and keeps the metallic-roughness map linear. **Nanite is off** on every part, as on the old cast (it was on by default, and its fallback mesh hid the vertices the fits are read from).
2. **`M_CastModel` gets a `RoughFromG` switch** (0 by default, 1 on every new instance): its `RoughTex` read R, which is 255 on these packed glTF maps; G holds the roughness. No metallic input was added: only Meta's chain is metal in the maps, and it reads as gold clay. Its default textures now point at `T_OpenAI_Head_*`, since the old ones were deleted.
3. **My box head is one mesh.** Hyper3D's agentic head came as 9 meshes, and Interchange wouldn't combine them (`CombineStaticMeshesBehavior` was ignored), so the 9 were merged with `StaticMeshEditorSubsystem.merge_static_mesh_actors` (temporary actors, gone after) into `SM_You_Head`: 27,074 triangles, 4 slots. The paint slot keeps T83's `MI_YouHeadPaint` (it grays on the cut); the liner, fibres and board keep the importer's flat glTF materials (`MI_You_Head_Liner`, `_Fibres`, `_Board`).
4. **The screens are flush, not recessed.** The prep read them as recesses from the turnarounds, but on the meshes each screen is the head's own curved surface (the dark is texture). So the face sits on the surface: each head's eyes 3 cm under it, the mouth 1 cm proud, and `Visor` moves inside the head (0, 0, 120, scale 0.4), where it is never seen and never wins `ScreenX`. `FaceRest`'s shell is an ellipsoid fitted to each head's front (centre z and radii in the Rig: OpenAI 116 and 41 x 46 x 44, Anthropic 119 and 40 x 44 x 42, SpaceXAI 125 and 28 x 34 x 34 without its nose, Meta 112 and 28 x 38 x 46).

### Unreal MCP and editor rules found in this task

- **Editor Python in one call, any size:** write the script to a file, then `SlateInspector.Click` and `Type` `py "<file>"` into the status bar's `Cmd` box (ref `tb9` this session), all inside one `execute_tool_script`. Have the script write its result to a JSON file and read that with Bash, so nothing big comes back through MCP. `from editor_toolset.toolsets.blueprint import BlueprintTools` works inside such a script: `BlueprintTools.write_graph_dsl(graph, code)` with a graph from `BlueprintTools.list_graphs(bp)`.
- **`Tools/dslpp.py` needs a `;;; GRAPH <Name>` line** at the top of its input, or it writes an empty file without an error. Writing that empty text with `write_graph_dsl` empties the graph. Add the line, expand, then strip it.
- **Components from Python:** `SubobjectDataSubsystem.k2_gather_subobject_data_for_blueprint`, `delete_subobjects(root_handle, handles, bp)`, `add_new_subobject(AddNewSubobjectParams(...))` and `rename_subobject`; `SubobjectDataBlueprintFunctionLibrary.get_object` gives the template to set. `get_editor_property('simple_construction_script')` is not exposed.
- **Screenshots to a file:** `AutomationLibrary.take_high_res_screenshot(w, h, path)` after `UnrealEditorSubsystem.set_level_viewport_camera_info`. Reading the PNG costs far less than `CaptureViewport`'s base64. But a Slate post-tick callback (for timed shots in Simulate) stalls while the editor sits in the background, so long sequences run late and out of step; `emote_test` (the robots cycle by themselves) plus wide shots every second, matched to the `NHOS: EMOTE` lines by timestamp, is reliable.
- **Game-window captures:** look the window up again before each `screencapture -l<id>`: the first window found is the splash screen, which closes.
