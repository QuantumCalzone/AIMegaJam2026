# T112 Spike: the stage on the mobile renderer, for Android and the web

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** my questions on 2026-11-19, in T91's session: can we upload Android builds, and would UE 5.9 give us web builds? Both are possible, and both run the stage on the mobile renderer.
  - **Android:** UE 5.8.4 packages for Android on Windows, with Android Studio and the SDK, NDK and JDK versions that 5.8 asks for. itch.io takes an `.apk`, and butler can push it to an `android` channel.
  - **The web:** UE 5.9 Preview 1 (2026-11-09) has an experimental web target (WebAssembly and WebGPU). It needs an engine built from source, a C++ project, the mobile renderer and Chrome, and reports cite a 2 GB memory ceiling. Epic expects the full 5.9 release in 2027 and says parts of the web renderer are prototypes.
  - **The common question:** the stage uses Lumen, hardware ray tracing, Virtual Shadow Maps and Substrate at desktop quality. How does it look and run without them? This spike answers that, and changes nothing on `dev`.
- **Rules:**
  - Work in a throwaway copy of the project outside the repo folder (for example `C:/Users/Personal/Projects/NHOS_mobile`, made like the deploy worktree), with its own editor. Never save an asset in the repo folder, and never move the repo's project to 5.9: assets saved in 5.9 don't open in 5.8.4, and `CLAUDE.md` holds everyone on 5.8.4.
  - Download nothing (Android Studio, the SDK, NDK or JDK, a 5.9 engine) without my OK. Give the size when you ask.

  6. **A recommendation for my verdict:** go or no-go for Android now, and for the web at the full 5.9 release, with a rough task list for each go.
