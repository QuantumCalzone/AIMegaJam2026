# T119 The three glow props glow in the packaged game

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** T92 found it on 2026-11-20. The cook of the release `10f8540` warns three times: "Failed to compile Material for platform SF_METAL_SM6, Default Material will be used in game", each with "(Node TextureSample) Sampler type is Grayscale, should be Linear Grayscale" for the material's glow mask. The materials are `M_GlowStickSword` (`Content/NHOS/Stage/Props/space_plans/`), `M_GlowingBriefcase` (`glowing_briefcase/`) and `M_GlowingStaff` (`mine_bridge/`), with the masks `T_GlowStickSword_Glow`, `T_GlowingBriefcase_Glow` and `T_GlowingStaff_Glow`. The packaged Mac game logs the same for the glow-stick sword, so those three props show the engine's default gray material instead of their glow. T105 found this and set the samplers to Linear Grayscale ("Glow" in its findings, and its later PIE shots show the glow), but the materials in git still have Grayscale: the fix never reached a commit. The check doesn't depend on the platform, so the Windows build most likely has the same three gray props.
- **Steps:**
  1. **Look.** Read "Glow" in T105's findings (`Docs/tasks/T105.md`). Open each of the three materials and its glow mask: the mask's sRGB is off (linear), and the material's `TextureSample` has Sampler Type Grayscale. Search the other materials under `Content/NHOS/` for the same mismatch (a `TextureSample` whose sampler type doesn't match its texture's compression and sRGB); the cook named only these three.
  2. **Fix.** Set each glow `TextureSample` to Sampler Type **Linear Grayscale**, keep the color and strength T105 chose (mint 6, warm gold 3, icy white 8), recompile and save. Don't change the textures: the mask must stay linear.
  3. **Check in the editor.** Each material compiles with no error, and its preview shows the glow. In PIE (Test for Free), screenshot each prop on the table in a scene that uses it (the space_plans card has the sword; find the cards with the briefcase and the staff in `Content/NHOS/Data/`).
  4. **Check in a build.** After the push, Tools > itch.io > "Dry run of dev" on the machine that ran the task: its log (`Saved/Logs/DeployItch.log`) has no "Failed to compile Material" line. On the Mac, also check the packaged game's log after a free autoplay show, as T92's findings say.
- **Done when:** the three materials use Linear Grayscale for their glow masks in git; "Dry run of dev" cooks with no "Failed to compile Material" warning; the PIE screenshots show the three props glowing; a free autoplay show reaches `NHOS: SHOW END`.
