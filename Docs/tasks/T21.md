## Findings

### T21: how a judge plays (2026-11-15)

- **Before a relay show** (the title's **Play via Relay**), `BPC_LLMClient.CheckRelay` sends `GET <relay>/health` through a new component, `BPC_HttpGet`: a copy of `BPC_LLMRequest` whose hand-wired Http Request node has its verb pin set to `Get`. `OnHealth` passes only when the reply is JSON with `budget_left: true` and at least 3 `providers`. The title polls `HealthResult` on its tick ("Checking the AI relay..."), then starts the show or calls `ShowUnavailable`. Prints `NHOS: HEALTH check`, `NHOS: HEALTH ok providers=<n>` or `NHOS: HEALTH fail <why>`. Autoplay runs skip the title, so they skip this check; the mid-show path still covers them.
- **The unavailable screen** is a new widget, `WBP_Unavailable` (a copy of `WBP_Keys`'s frame), so `WBP_Stage` didn't change. It shows the reason (`DownText`) and three buttons: **Use my own API keys** (opens `WBP_Keys` above it), **Test for Free** and **Back to title**. `ShowUnavailable(Msg)` makes it (z-order 40) and `CloseUnavailable` removes it. Prints `NHOS: UNAVAILABLE shown <msg>`.
- **Mid-show:** in relay mode, `HandleHttp` sends an ask whose error type is `session_limit`, `player_limit`, `budget_used_up` or `provider_unavailable`, or that fails transport after its one retry, to `GoDown(Msg)` instead of `Deliver`. `GoDown` sets `Down`, prints `NHOS: SHOW UNAVAILABLE relay <msg>` and shows the screen with the relay's own `error.message` (`ParseReply` now keeps `ErrType` and `ErrMsg`). While `Down`, `Ask` holds new asks and `HandleHttp` drops late replies, so the show freezes behind the screen instead of playing on with robots that only look around.
- **Switching mode mid-show** reloads the level: `Relaunch(NewMode)` calls `OpenLevel L_Stage` with the option `nhosmode=<mode>` when a show has started (`ShowOn`, set in `StartShowSession`); before a show it returns false and the widget calls `StartFromTitle` as before. `LoadConfig` reads the option with `ParseOption`, sets the mode and `Relaunched`, and `BP_Show.ShowTitle` skips the title when `IsRelaunch` is true (`NHOS: TITLE skipped relaunch`). **Back to title** relaunches with no mode.
- **Key test:** `TestKeys` sends one small real ask (the provider's model, effort and reply schema, `BuildBody`) to each provider that has a key, tagged `keytest-<provider>`; `HandleHttp` routes those tags to `OnKeyTest`. A transport failure, an API error or an unreadable reply fails that key; `finish_reason`/`stop_reason` cut-offs pass, because the key worked. `KeyTestResult` says when all have answered. `WBP_Keys` polls it on its tick: **Save and Play** saves, checks for 3 keys (`SetMode keys`), tests, and starts (or relaunches into key mode) only if every key works; the new **Test keys** button runs the test without starting. The note never shows a provider's error text, only the lab and the error type (for example "Key test: Anthropic: the key didn't work (authentication_error)."), because some providers echo part of the key.
- **PIE checks (Test for Free unless noted, no tokens spent):** a free autoplay show reached `SHOW END result=win` with 88 `ok` lines, before and after the change. Wrong relay address (`https://no-such-relay.invalid`): **Play via Relay** gave `HEALTH fail transport ConnectionError` and the unavailable screen, and **Use my own API keys** opened the key screen above it. **Test keys** with no keys: "Paste at least one key to test."; with a fake Anthropic key: one real call answered `authentication_error`, shown as above. A local stub relay (`/health` ok, every ask `budget_used_up`; see the Relay README's error shape): **Play via Relay** passed the health check, the first ask failed, and the screen showed the relay's message ("The free AI budget for today is used up. ..."); the three asks still in flight were dropped. **Test for Free** there relaunched the level in free mode and a free show started without the title. The real relay's `/health` answers `{"ok":true,"providers":["anthropic","openai","xai","meta"],"budget_left":true}`.
- **Not checked:** a key-mode show with real keys (see "Key-mode check" above), and a real relay show through the new health check (the relay path itself is unchanged since T18).
- **Fixed on the way:** `BP_Show.DrawCast` added every seated persona's provider to the "left out" list too, so `NHOS: DRAW` named all four providers; the add is now in an `else`. `SetKey` prints `NHOS: KEY set <provider> chars=<n>` (never the key).
- **My calls (2026-11-15):** a hard monthly spending limit is set at all four providers. The relay keeps its limits for judging: 150 calls per show, 600 per player per day, 5,000 a day for everyone.
- **Unreal MCP:**
  - **Setting a property on a live PIE actor's component** (`ObjectTools.set_properties` on `BP_Show_C_0.LLMClient`) reruns the actor's construction script and resets its Blueprint variables (`PersonaArr`, `Ready`), so the next show draws 0 AI seats. To test another relay address, change `relay` in `llm.json` for the run and put it back. `set_properties` also refuses a variable that isn't instance-editable.
  - **A widget can run a stale compile in PIE** (T14 saw the same): `WBP_Keys`'s `SetKey` calls didn't run until `WBP_Keys` was compiled again. Compile each widget you change before PIE.
  - **The editor's MCP server can fail to start after a restart** (`HttpListener unable to bind to 127.0.0.1:8000` in the log, while the old process still holds the port). The console command `ModelContextProtocol.StartServer` starts it; `ModelContextProtocol.StopServer` also exists.
  - **SlateInspector clicks on PIE widgets are often lost,** not only the first one: click, check the log for the button's `NHOS:` line, click again.
  - A duplicated widget keeps its old event graph; delete its nodes (`find_nodes` with an empty title returns them all) before writing a new one, and bind each renamed or new button with `UMGToolSet.BindToEventProperty` first.

### T21: the key-mode check (2026-11-15)

- **How it ran:** in PIE on the Windows PC, as "Key-mode check" above says, with keys for all four labs in `Local/llm_key.json`. `relay` in `llm.json` pointed at `https://no-such-relay.invalid` only until the client printed `NHOS: CLIENT ready mode=free keys=4`. The client reads `relay` once, at load, so I put the real address back right then, before any click. A mode switch before a show calls `StartFromTitle` and doesn't reload the level, so nothing reads the file again.
- **The path, as the log shows it:** **Play via Relay** gave `HEALTH check`, `HEALTH fail transport ConnectionError` and `UNAVAILABLE shown The relay that plays the AIs did not answer. It may be down, or you may be offline.` **Use my own API keys** gave `KEYS shown`. **Save and Play** gave `KEY set <provider> chars=<n>` for all four, `KEYS saved=true count=4` (it writes the same keys back to the file), `MODE keys` and `KEYTEST start keys=4`. Then `KEYTEST anthropic ok`, `meta ok` and `openai ok` within 2 s, `xai ok` after 7.3 s, then `KEYS tested ok=true`, `KEYS start` and `TITLE play`. `DRAW ai=4 providers=` now leaves no provider out, so the `DrawCast` fix holds.
- **The show:** the first scene's four asks all came back `ok` with `mode=keys`: Meta in 0.65 s, Anthropic in 1.3 s, OpenAI in 2.0 s and xAI in 8.0 s, after one retry. Each read 2,500 to 3,800 tokens and wrote 54 to 139. I stopped PIE at my first turn, so the check spent 4 key tests and 5 calls, a few cents.
- **xAI at capacity:** xAI's first answer was plain text, not JSON ("The model is currently at capacity due to high demand ..."). `ParseReply` can't read it, so the log shows `LLM overclocker-2 retry API error :  provider=xai` with an empty error type and message, beside `FJsonObjectWrapper::ImportTextItem - Unable to parse json` and `Field 'message' was not found`. The one retry got through. Its key test had passed 0.7 s before, so a passing key test doesn't promise that the provider has room. Not checked: what the relay sends the game when xAI answers it this way.
- **Keeping keys out of the transcript:** a SlateInspector `Snapshot` of the open `WBP_Keys` gives each masked key field a quoted label. I didn't look at what the label holds. To find the buttons, run the snapshot inside `ProgrammaticToolset.execute_tool_script` and return only the button lines, with any textbox label blanked. All three clicks (**Play via Relay**, **Use my own API keys**, **Save and Play**) worked the first time.
- **Git and the `relay` edit:** after a `sed -i` in Git Bash that changed `relay` and then changed it back, `git status` still showed `llm.json` as modified, though its hash matched HEAD (the file has LF endings and the checkout uses `autocrlf`). `git add` on the unchanged file cleared it and left its bytes alone.
