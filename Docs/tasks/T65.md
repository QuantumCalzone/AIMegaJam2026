## Task

- **Model and effort:** Opus 5.5, high. Key handling, focus and a pop-up list on the busiest widget.
- **Depends on:** T64 (the input row and Action!), T63 (the line's path)
- **Needs:** editor + Unreal MCP running, Test for Free for the PIE shows.
- **Touches:** `Content/NHOS/UI/WBP_Stage.uasset` (the speech field, the counter, `OnPreviewKeyDown`, the @ list), `Content/NHOS/UI/WBP_ActionBuilder.uasset` (the chip in the preview line), maybe `Content/NHOS/Core/BP_Show.uasset` (to hand the names on screen to the widget), `Graphs/` files for the graphs it writes, `Docs/tasks/T65.md`.

- **Why:** the input spec in [T62.md](T62.md) ("The input spec": row 3 of "Layout", and "Saying a line"). The input box becomes a speech field: I see how many words I have left, I never lose focus while I click, and I pick a name with @ instead of typing it. It takes over the @ half of T31, which was dropped on 2026-11-15.
- **Steps:**
  1. **The speech field** is the input box in the input row, with the hint "Say something (optional)...". To its right: a live word counter ("12/15"), then T64's Action!, then room for T66's timer.
  2. **The 15-word cap.** The counter counts words as `CapWords` does, so a mention is one word. It turns to `UIStyle`'s warning red at 15, and a 16th word can't be typed: when the text changes, cut it back to 15 words and keep the caret at the end. A paste is cut the same way.
  3. **Focus stays here.** The speech field holds keyboard focus for my whole turn. It takes focus when each of my turns opens, and again after any click on the builder, my card or the chat. T64 made the builder unfocusable; check that nothing else on the screen takes focus.
  4. **The @ list.** Typing "@" opens a small list above the field: the actors still in the show, by the names on my screen, in their colors, never me. Letters after the "@" filter it. Up and Down move in it; Enter, Tab or a click puts the name in; Esc closes it. While it is open, Enter picks a name and doesn't send. Catch the keys in `WBP_Stage`'s `OnPreviewKeyDown` and return Handled, because by default Tab moves the focus to the next widget (T31's note).
  5. **A mention is a chip.** A picked name shows as a chip in the actor's color. UMG's editable text can't hold a widget inline; if that proves true, insert "@Meta " as one unit (one Backspace right after it removes the whole mention) and draw it as a chip in T64's preview line. Write under "## Findings" what you built. It reaches the AIs as "@Player 5" through `ResolveMentions`, as it does now.
  6. **Speech never acts.** Nothing typed in the field changes the builder. (T63 already makes the input LLM leave actions alone.)
- **Done when:**
  - In PIE (Test for Free, autoplay off, a 1600 × 900 window), screenshots show: the hint in an empty field; the counter at 12/15; the counter red at 15, with a 16th word refused; "@" with the list of AI names (not me); "@me" filtered to Meta; the mention as a chip.
  - Typing, clicking Grab and typing on puts every letter in the field.

  - A free autoplay show in a game window reaches `NHOS: SHOW END` with no `LogScript` line.

### Three faults the check found in the sheet, fixed

1. **A `SetText` from the game fires no `OnTextChanged`.** The sheet relied on it after a pick (`AtPick`) and after a send (`SubmitInput`'s clear). Without the fix the preview kept the old line and the counter didn't reset. Now both call `SpeechChanged` themselves right after their `SetText`. (A typed edit, a Backspace and a real paste do fire it.)
2. **`UserInterface|Geometry|LocaltoAbsolute(Vector)` and `AbsolutetoLocal(Vector)` transform a direction and drop the position,** so the @ list sat in the top-left corner. The point transforms are the `(Coordinates)` nodes; `AtPlace` uses them, and the list now sits right over the field.
3. **`HoldFocus` took the keyboard back every frame while my input was open,** which also took it from the editor's own windows: an editor console command typed during PIE went into the speech field and was sent as my turn. It would take it from the game's console too. Now a new `OnPreviewMouseButtonDown` override notes any click in the game window (`ClickAsked`), and `HoldFocus` gives the focus back only after such a click. That is what step 3 asks for (after a click on the builder, my card or the chat), and the editor and the console keep their keyboard.

Also: in `AtDraw`, `(bind _was (V AtOpen))` before `(set AtOpen Open)` read the new value (a bind of a variable is a pure node, read where it's used), so no `MENTION open`/`close` printed and a re-opened list kept its old highlight. `AtDraw` now reads `AtOpen` before it sets it.

### Unreal MCP rules found in this task

- **A game-side `SetText` on an `EditableTextBox` fires no `OnTextChanged`;** call your change handler yourself.
- **The geometry point transforms are `LocaltoAbsolute(Coordinates)` and `AbsolutetoLocal(Coordinates)`;** the `(Vector)` ones drop the position.
- **A `bind` of a variable is a pure read,** evaluated where it's used: read a value you are about to `set` before the `set`, or copy it with a `set` into another variable.
- **`add_function_graph` with an inherited function's name makes an override** (`OnPreviewKeyDown`, `OnPreviewMouseButtonDown`).
- **`Class|Border|SetPadding` takes `:Padding`** (a property set), not `:InPadding`.
- **Saving a new widget:** `AssetTools.save_assets` says "Asset does not exist" for an asset that was never saved; `unreal.EditorAssetLibrary.save_loaded_asset` from the editor's Python console works. It returns false while PIE runs.
- **The editor's Python console through the Slate inspector:** set the Cmd box's text with `FillForm`, then `Type` "" with `submit`; a `Type` alone appends to whatever is in the box.
- **Reloading `BP_Show` together with a changed `BPC_LinePlayer` crashed the editor** (`LinePlayer ... doesn't match the property`, then `StaticShutdownAfterError`). Restart the editor after a pull that changes `BP_Show`'s components instead of reloading.
- **On this Mac, PIE needs full-screen computer use for clicks:** background clicks and Slate inspector clicks don't land. A 1600 × 900 PIE window is 800 × 484 points on the Retina screen.
