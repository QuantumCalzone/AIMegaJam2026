# T117 A live dashboard of the prod play stats, on the relay

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** my question on 2026-11-19: I want a dashboard to see the analytics, for the prod game only, never my own plays. Today `Tools/analytics_report.py` prints text, and only on a machine with the stats key in `Local/stats.json` (only the Mac has it). There were three choices: a page the relay serves, a local HTML report, or a Claude artifact refreshed on a schedule. I picked the relay page (2026-11-19), because it is always current, opens on any device, and needs no machine left on.
- **What changes:** the relay answers `GET /dashboard` with one page. I paste the stats key in a browser once, and the page keeps it there and draws the play stats from `/stats`. By default it shows the prod game only.
- **What "prod" means:** an event counts when all of these hold:
  - It is not a test event (T67, T68). T116 makes every event from my machines a test event, in any build.
  - Its player is not on the ignore list (step 2).
  - Its build is not `local`. Since T111, the editor and builds packaged by hand report `local`.

  Release labels (`YYYY-MM-DD-<sha>`, T111) count. So does the old label `2026-11-15`, which the jam's file and the first release (`2026-11-20-10f8540`, and its Mac file) both send. The relay can't tell a release from a dry run by its label. Only my machines play dry runs, and T116 makes their events test events.
- **Steps:**
  1. **Read first.** T67's file (`/event`, `/stats`, the `Stats` store, and why it is not Workers Analytics Engine), T68's (what the game sends), T111's (the build labels) and T116's (the marker). Then read `Tools/analytics_report.py`, whose sections the page mirrors, and "Analytics events" and "Run it locally" in `Relay/README.md`.
  2. **The ignore list on the relay.** Add a Worker variable, `IGNORE_PLAYERS`: player ids, separated by commas. The ids are anonymous, so it need not be a secret. `/stats` returns the list with the events, as `"ignore_players": [...]`, and `analytics_report.py` merges it with `ignore_players` in `Local/stats.json`. In `Relay/README.md`, list this PC's ids from T68's findings as the first to add (editor `04fdad454871396e06204ca99147e9f0`, package `57522c4c49c7c264112a798edc66b745`). They cover the events from before T116. I set the variable myself in the Cloudflare dashboard.
  3. **The page.** One HTML file that the Worker serves at `/dashboard`. The page needs no key, because it holds no data. Put everything inline, with no outside script, font or style, because the key lives in the page's storage. Send a `Content-Security-Policy` that allows only the page itself and calls to `/stats`. The page asks for the key and keeps it in `localStorage`, with a "Forget key" button. It reads every page of `/stats` (`since`, `after`, `limit=5000`) and works out the numbers in the browser, as the report does. A wrong key says "wrong key", not an empty dashboard.
  4. **What it shows.**
     - Players and shows per day, with the players who came back.
     - Shows per mode.
     - The drop-off: shows that reached each phase, and the `show_end` results.
     - Calls and failures per provider and model.
     - Errors by kind.
     - The most common unsupported actions.
     - A builds table, newest first.

     Controls: a start date (`since`), a build picker (every prod build, or one build), and a switch, "Show test events and ignored players", for checks. Draw the charts as inline SVG. The page reads well at phone width (a 16 px side gutter and no sideways scroll), and in dark mode.
  5. **Scale.** Time a full read at the current number of events. If it takes more than a few seconds, add a summary answer to `/stats` that the `Stats` store works out instead. Write why under "## Findings".
  6. **Tests and docs.** Add `/dashboard` checks to `Relay/test/curl-tests.sh`: the page answers HTML with the CSP header, and `/stats` answers `ignore_players`. Add a "Dashboard" section to `Relay/README.md`: the address, the key, the variable and what "prod" means. It also says that the page goes live with the next release, because the relay deploys from `main` (T91).

  6. No key is in git or in this chat.
