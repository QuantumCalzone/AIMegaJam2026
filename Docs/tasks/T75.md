# T75 Each robot can show an emotion: its face and a gesture

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** I want the AI players to emote: to look confused, angry, worried and every other basic human emotion while they act, so the stage feels alive and a face can give a bot (or me) away. This task is the robot half: each robot can act out any emotion on cue. T76 makes every AI reply carry an emotion, T77 plays it when the line plays (my robot too), and T78 lets me pick mine. This task touches neither `BP_Show` nor `WBP_Stage`, so the machine that isn't on the editor chain can take it.
- **Steps:**
  1. **The emotions are data.** A new `Content/NHOS/Data/emotes.json` holds the list, with a `_readme` as an array of lines. Start with these 12 ids: `neutral`, `happy`, `sad`, `angry`, `worried`, `scared`, `surprised`, `confused`, `disgusted`, `suspicious`, `smug` and `embarrassed`. Each entry has:
     - `word`: the plain word T77 writes in the shared log ("worried"). `neutral` has an empty word.
     - `face`: the face's pose. The eyes' scale (x and y), height and tilt; the brows' angle and height; the mouth's width, height and curve (or tilt, whatever the `Mouth` bar can do); an optional LED tint (a red tint for angry, for example). `neutral` is today's face, value for value.
     - `gesture`: one of the gestures in step 4, or `none`.
     - `hold`: the seconds the emotion stays before the face eases back to neutral (start near 3, about one line's reading time).
     Adding an emotion later should need only a new entry that uses the gestures that exist (plus T76's list in `llm.json`), with no editor work.
  2. **`BP_Robot.Emote(Emotion)`** reads `emotes.json` once (at `Setup`, or the first call) and eases the face to the entry's pose in about 0.2 s. Then it plays the gesture, holds for `hold` seconds or until the next `Emote`, and eases back to neutral.
     - An empty or unknown id is `neutral`. An unknown id also prints `NHOS: EMOTE unknown <id>`.
     - A cut robot doesn't emote, as `Shake` and `Cheer` already work.
     - Each call prints `NHOS: EMOTE <seat> <id>`.
     - The talking mouth (T46's stretch on Event Tick) rides on top of the emotion's mouth, so a bot can talk and look worried at once.
  3. **Brows for every bot.** Most emotions read through the brows, but only the Anthropic and SpaceXAI bots have brows today (T46). Give every robot LED brows that show only while it shows an emotion other than neutral, and keep the Anthropic and SpaceXAI bots' resting brows as they are. The Meta bot's fixed `Smile` must make way for the emotion's mouth while it emotes. My robot keeps its big eyes, bent antenna and scarf. Write what you chose under "## Findings".
  4. **The gestures,** built on the robot's act clock like `Shake` and `Cheer` (`TickActs`). The emotions share a small set. Start from these, and change any that don't read:
     - `bounce`: happy. Little hops.
     - `slump`: sad. Sinks and tips forward.
     - `shake`: angry. The shake that exists, a little harder.
     - `tremble`: worried and scared. A fast, small shiver.
     - `jolt`: surprised. A quick hop back.
     - `tilt`: confused. The body rocks side to side.
     - `recoil`: disgusted. Leans away.
     - `lean_in`: suspicious. Leans forward with narrowed eyes.
     - `puff`: smug. Grows a little and leans back.
     - `shrink`: embarrassed. Sinks a little and turns partly away.
     A gesture never moves the robot off its mark and never cuts into a move, grab, give or throw. While the robot walks, only the face changes.
  5. **A test switch.** `"emote_test": true` in `Local/switches.json` (add it to `Docs/switches.example.json`, off) makes each robot cycle through every emotion by itself from `BeginPlay`, a few seconds each, each robot starting at a different emotion. A session can then screenshot them all with no LLM and no `BP_Show` change.
  6. **The checker.** `Tools/check_prompts.py --offline` checks `emotes.json`: `neutral` is there, every entry has every field, each value is in a sane range, and each gesture is one the robot knows. (T76 adds the check that the reply's emotion list matches these ids.)
- **Done when:**
  - In PIE (Test for Free, `emote_test` on, the house camera), there is a screenshot of each emotion on at least one robot, plus one frame with all five robots on different emotions. A close-up of one face per emotion is fine where the house camera is too far.
  - Under "## Findings", Claude judges from the screenshots, as a critical first-time player would, whether each emotion reads from the house camera with no label. It names any two that look alike, and reworks them, or drops one from `emotes.json` and says so, before the task closes.
  - The log prints `NHOS: EMOTE` for each emotion, and no `LogScript` line.
  - With `emote_test` off, a free autoplay show in a game window reaches `NHOS: SHOW END`, and the robots look as they did before (neutral) and still act out their moves.
  - `python Tools/check_prompts.py --offline` passes. `emote_test` is set back to false.
