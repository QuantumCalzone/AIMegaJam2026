# T48 The seven painted backdrops

Back to [the plan](../Plan.md). Done on 2026-11-15; its entry there is cut down to its title line and this link.

## Task

- **Model and effort:** Opus 5.5, high. Seven images picked by eye, and a backdrop material that the stage lights don't wash out.
- **Depends on:** T44 (the backdrop ids), T39 (the tool). Steps 1 and 2 (making and picking the images) need no editor and can run as prep once T44 is done.
- **Needs:** the Leonardo key in `Local/` and a few dollars of its API credit, editor + Unreal MCP running, Test for Free for the PIE shows.
- **Touches:** new `Docs/BackdropArt/` and `Docs/BackdropArt.md`, `Docs/Assets.md`, new `Content/NHOS/Stage/Backdrops/`, `Content/NHOS/Stage/M_Backdrop.uasset`, `Content/NHOS/Stage/BP_Backdrop.uasset`, `Graphs/BP_Backdrop/` files for the graphs it writes.
- **Why:** each story drops in its own painted backdrop (the design doc's "Art Inspiration" tab, Props and backdrops). Today `BP_Backdrop` (T17) shows a two-color sky and a few cardboard cutouts per backdrop id.
- **Steps:** steps 1 and 2 need no editor.
  1. **Make the images** with `python Tools/art_gen.py image --width 2048 --height 1024`, one per card, from the `backdrop_prompt` in each `Docs/StoryDrafts/` file: a stop-motion clay relief diorama, no characters, text or logos. Pick the best of four for each, by eye, as T40 does. Keep the theater's warm palette, and leave the lower part of each image plain, where the robots stand in front of it.
  2. Save the picks as `Docs/BackdropArt/<backdrop id>.png`, with the prompt and seed in `Docs/BackdropArt.md`, and a row each in `Docs/Assets.md`.
  3. **Import** them into `Content/NHOS/Stage/Backdrops/` as `T_Backdrop_<id>` (`TextureTools.import_file`).
  4. **Show them:** `M_Backdrop` gets a texture parameter (Substrate, unlit-looking: the image's color as emission, so the stage lights don't wash it out), and `BP_Backdrop.ShowBackdrop(Id)` sets the card's texture and hides the old cutouts. An unknown id keeps the plain dark flat.
  5. **Check:** a screenshot of each of the seven backdrops from the house camera (`PreviewBackdrop`); a free autoplay show reaches `NHOS: SHOW END`.
- **Done when:** the check passes, and Claude checks from screenshots of one free show in a game window that the backdrops fit.

- **Result:** done. Each of the seven cards' backdrop ids shows its own painted clay picture on the backdrop flat: 2048 × 1024 Leonardo images picked from four by eye (`Docs/BackdropArt/`, `Docs/BackdropArt.md`, 7 rows in `Docs/Assets.md`), imported as `Content/NHOS/Stage/Backdrops/T_Backdrop_<id>`. `M_Backdrop` gained `Art` (texture), `UseArt`, `ArtGlow` (4) and `ArtLit` (0.05): with `UseArt` at 1 the picture is mostly emission, so the stage lights don't wash it out. `BP_Backdrop` has `ArtIds` and `ArtTex` (seven each), and `ShowBackdrop(Id)` sets the picture and hides every T17 cutout when the id has one; an unknown id keeps the plain dark flat. House-camera captures of all seven and of an unknown id look right, and a free autoplay show in a game window reached `NHOS: SHOW END result=win reason=last_scene scenes=4` over four backdrops, with no script error. 536 Leonardo API credits.

## Findings

### What was built

- **Images (steps 1 and 2).** One Leonardo `lucid-origin` generation of four per card at 2048 × 1024, from each `Docs/StoryDrafts/` file's `backdrop_prompt` plus a shared composition suffix (interest in the upper left, upper right and middle band; calm top center; plain bottom third; warm opera-house palette) and a negative prompt. `Docs/BackdropArt.md` has the suffix, the negative, every pick's generation id and seed, and why each was picked; `Docs/BackdropArt/logs/` has the full logs. The run was a small script over `art_gen.leonardo()` that checked the balance before each card, not `art_gen.py image` by hand, so the cap could be kept.
- **Textures (step 3).** `TextureTools.import_file`, sRGB, default compression, 2048 × 1024.
- **`M_Backdrop` (step 4).** Its old graph is kept: the two-color sky (`Top`, `Bottom`, `Bright`) still feeds the slab when `UseArt` is 0. New: `LocalPosition` into a Custom node (`BackdropUV`) that maps the flat cube's −X face to UVs, with +Y to the right and the image's 2:1 aspect kept (the flat is 13 × 6.2 m, so 30 of the image's 650 units are cropped at the bottom, where it is plain floor); `Art` sampled there; `Lerp(sky × Bright, Art × ArtGlow, UseArt)` into Emissive and `Lerp(sky × 0.35, Art × ArtLit, UseArt)` into Diffuse Albedo. Local position, not UVs or world position, so the picture fits the face wherever the actor stands.
- **`BP_Backdrop` (step 4).** Two new array variables, `ArtIds` (string) and `ArtTex` (Texture2D), set on the class defaults. They are hard references, so a cook that only takes `L_Stage` still packs the seven textures. `ShowBackdrop` (source in `Graphs/BP_Backdrop/ShowBackdrop.txt`) finds `Id` in `ArtIds`, hides every `bd`-tagged cutout when it is there, sets `Art` on the flat's dynamic material and `UseArt` to 1 or 0, and still sets the old sky colors. `BP_Show` is unchanged: it already calls `ShowBackdrop` with the card's id in `StagePrep`.

### Decisions made for my person

- **The spend.** You OKed 400 Leonardo credits, then 550 when one card turned out to cost 67 credits (about 17 per 2048 × 1024 image). 8 generations: 7 cards and one retry, 536 in all.
- **One retry, on the diner.** All four first diner candidates had fake lettering on a sign or neon. The retry's prompt led with stronger clay words and banned signs and neon; its candidate 3 has no lettering.
- **The dwarf mine is candidate 4**, the darkest picture, because it has the thin stone bridge over the glowing chasm that the card describes. Candidate 2 (brighter, a wide arch instead) is the fallback if it reads too dark in play.
- **`ArtGlow` 4.** At 1 the pictures were dim and gray next to the lit stage, at 2.5 still muted; at 4 the colors match the source images without blowing out the brightest one (the garden wedding's white tent and sky).
- **The old sky and cutouts stay** for ids with no picture (T17's six old ids), so nothing that still names them breaks. No current card uses them.

### Unreal MCP and editor rules found in this task

- **`AssetTools.read_file` reads only under `Content/` and `Saved/`**, not `Graphs/`. Copy a DSL file to `Saved/` to push it.
- **`ObjectTools.get_properties` takes `instance` and `properties`; `set_properties` takes `instance` and `values`, a JSON string.**
- **In the DSL, `(Actor|GetComponentsByClass "<class>")` with the class as a positional argument leaves the output typed as ActorComponent**, and `SetVisibility` then fails to connect. Pass it as `:ComponentClass "/Script/Engine.StaticMeshComponent"`. A read-back of the old graph prints the positional form, which is another way a read-back drops data.
- **`Rendering|Material|CreateDynamicMaterialInstance` resolves to the PrimitiveComponent version** (self, ElementIndex, SourceMaterial); with no source material it reuses the MID that `SetVectorParameterValueOnMaterials` already made.
- **Leonardo serves JPEG data under the `.png` name.** Convert with `sips -s format png` before you commit or import.
- **The Leonardo API key is shared:** another session or machine made robot-character images on it while this task ran (353 credits). `GET /v1/me` (`apiPaidTokens`) shows only the total, so count your own cost per generation, and read `GET /v1/generations/user/<id>` to see whose generations they were.
