## Task

- **Model and effort:** Opus 5.5, high. It sorts every error path in the client into cases, and adds one note that crosses the client, the show and the banner.
- **Depends on:** T29 (the banner), T30 (the banner waits for the line queue), T33 (it lays out the key screen and the unavailable screen that show these lines). T21 is done.
- **Needs:** editor + Unreal MCP running, Test for Free with the new `error_test` switch for the PIE shows, T21's local stub relay for the budget message, and one fake Anthropic key for the key test (no tokens). No relay or key-mode show.
- **Touches:** new `Content/NHOS/Data/errors.json`, `Content/NHOS/Core/BPC_LLMClient.uasset` (new `ErrorKind` and `ErrorLine`; `ParseReply`, `HandleHttp`, `OnHealth`, `OnKeyTest`, `KeyTestResult`, `SetMode`, `Deliver` and the free-mode path for `error_test`), `Content/NHOS/Core/BP_Show.uasset` (one node that shows the note on the banner; in the end not touched, see Findings), `Content/NHOS/UI/WBP_Stage.uasset` only if the banner needs a longer hold for a note, `Tools/check_prompts.py`, `Docs/switches.example.json`, `Graphs/` files for the graphs it writes.
- **Why:** my request on 2026-11-15. Error messages should be funny but still tell me what actually went wrong. For example, when a key runs out of credits, the game can joke that the key's owner is cheap. Today the screens use flat text, and a robot whose reply failed just looks around: an out-of-credits key, a rate limit or a lab at capacity looks the same as a robot with nothing to say. The design doc's tone is "playful, petty slapstick" (Art Inspiration), and its Tech & Build tab now asks for this rule.
- **Where error text comes from today** (found on 2026-11-15, all in `BPC_LLMClient`):
  - Before a relay show, `OnHealth` sets one of 4 fixed messages for the unavailable screen.
  - During a relay show, `HandleHttp` calls `GoDown` with the relay's own `error.message` (`MESSAGES` in `Relay/src/index.js`), or with a fixed line when the relay stops answering.
  - On the key screen, `OnKeyTest`, `KeyTestResult` and `SetMode` write the notes ("Anthropic: the key didn't work (authentication_error).").
  - During any show, a reply that fails after its one retry goes to `Deliver` with `Ok` false. `BP_Show` then makes the robot look around (a scene turn), pass (Free Talk) or stay silent (a reaction), and I'm told nothing. Through the relay, any failure at the lab (for example xAI at capacity) comes back as `provider_error` with the lab's HTTP status in `upstream_status`, and ends the same way.
- **Steps:**
  1. **The lines go in a data file,** new `Content/NHOS/Data/errors.json`: one entry per case in "Approved lines" below, each a list of 2 lines, and the game picks one at random. Fill in `{lab}` (the provider's display name from `personas.json`: OpenAI, Anthropic, SpaceXAI or Meta), `{n}` and `{type}`. Every line says what happened in its first sentence, then makes the joke. Keep each approved line as it is and write a second one for each case in the same voice. Add a `_readme`. Add an `--offline` check of the file to `Tools/check_prompts.py`: every case has a line, no unknown placeholder, and no line uses a persona name.
  2. **Sort each failure into a case,** with a new function, `BPC_LLMClient.ErrorKind`. It reads `ErrType` and `ErrMsg` (the error's `type` and `message`, which `ParseReply` already keeps), the relay's `upstream_status` (make `ParseReply` keep it too) and the reason that `HandleHttp` builds (`transport ...`, `finish_reason ...`, `stop_reason ...`, `refusal ...`, `reply is not JSON: ...`). Check in this order:
     - `transport`: **no reply**.
     - The relay's own types (`session_limit`, `player_limit`, `budget_used_up`, `provider_unavailable`): each is its own case.
     - **Out of credits:** type `insufficient_quota` or `billing_error`, or the message has "credit", "quota", "billing", "balance" or "spending limit".
     - **Rate limited:** type `rate_limit_error`, `rate_limit_exceeded`, `requests` or `tokens`, or the message has "rate limit" or "too many requests". Through the relay, `upstream_status` 429 is **relay 429**, because the relay can't tell a rate limit from our spending cap.
     - **Overloaded:** type `overloaded_error`, or "overloaded", "capacity" or "high demand" in the message, or `upstream_status` 503 or 529.
     - **Key rejected:** type `authentication_error`, `permission_error` or `invalid_api_key`, or "api key" in the message.
     - **Cut off:** `finish_reason length`, `stop_reason max_tokens`. **Refused:** a refusal, `content_filter`.
     - **Can't be read:** not JSON, or no text, with no keyword above. A plain-text reply goes through the keyword checks first, so xAI's "The model is currently at capacity ..." lands on **overloaded**.
     - Any other relay `provider_error`: **relay provider**. Anything else: **unknown**.
     - The provider's message is read only for these keywords and never shown, because some providers echo part of the key (T21).
  3. **One function makes the text,** `ErrorLine(Kind, Lab, N, Type)`, and every place that writes error text today uses it: `OnHealth`, both `GoDown` calls in `HandleHttp`, `OnKeyTest`, `KeyTestResult` and `SetMode`. For a relay type that `errors.json` has no line for, the relay's own `error.message` stays the fallback. Key-test notes keep the lab and the error type in parentheses, never the provider's text. Print `NHOS: ERROR <kind> provider=<id> where=<health|down|keytest|turn>` each time.
  4. **A backstage note during the show.** When an actor's reply fails after its retry, the client passes `BP_Show` the line, and one node in `BP_Show` shows it on T29's banner (`EventBanner`), long enough to read (about 6 s; T30's line queue decides when it shows). The robot still looks around, passes or stays silent as now. Show at most one note per lab per scene, so a lab that keeps failing doesn't fill the show.
     - The note is for my screen only. It never goes in the shared log the AIs read (the build notes keep errors out of it, and the note names the lab, which the AIs must never see) or in `game_messages`.
  5. **A test switch, so the checks cost nothing.** `"error_test": "<case>"` in `Local/switches.json` makes Test for Free fail one actor ask per turn with a canned reply body for that case, sent through the real `ParseReply`, `ErrorKind` and `ErrorLine`. Make each body realistic: OpenAI's `insufficient_quota` JSON, Anthropic's credit-balance and `overloaded_error` JSON, xAI's plain-text "at capacity" reply, a `finish_reason: length` reply, and so on. Add the switch to `Docs/switches.example.json`.
  6. Don't change the relay. Its `MESSAGES` stay as they are.
- **Done when:**

## Findings

### T37: what was built

- **No `BP_Show` change (my call, 2026-11-15).** The plan had the client hand the note to one new node in `BP_Show`, which only the PC's chain may save. The session found a way with none: `BPC_LLMClient` is a component on `BP_Show`, so `BackstageNote` finds its sibling `BPC_LinePlayer` with `Actor|GetComponentbyClass` on its owner and calls `Cue("banner", <note>, 0)`, the same call `BP_Show.CueBanner` makes. I picked that over the node. The note waits for the lines in front of it (T30's queue), and `RunCue`'s `banner` branch shows it with `WBP_Stage.ShowBanner`. T52's newer `RunCue` keeps that branch. Cost: the client now references `BPC_LinePlayer` (which references `BP_Show`), a loop like the one `BP_Show` and `BPC_LinePlayer` already have.
- **`errors.json`** (T37 prep wrote the cases and their offline check): one list of two lines per case, `_readme`, and now `test_replies`, the canned reply bodies for `error_test`. Each names its `kind` and holds a body per format (`openai_chat`, `anthropic`), one for `any`, or `transport` (the request itself fails): OpenAI's `insufficient_quota` and Anthropic's credit-balance JSON, both labs' rate limits, xAI's plain-text "at capacity" reply, Anthropic's `overloaded_error`, OpenAI's `invalid_api_key` (with a masked key in the message, as OpenAI sends it) and Anthropic's `authentication_error`, a timed-out request, `finish_reason: length` and `stop_reason: max_tokens`, `content_filter` and `stop_reason: refusal`, an HTML 502 page, the relay's `provider_error` with `upstream_status` 429 and 500, and OpenAI's `server_error`.
- **New client functions** (sources in `Graphs/BPC_LLMClient/`):
  - `ErrorKind(Reason)`: the order of step 2. The keyword text is `ErrMsg`, plus the reason only when the reply couldn't be parsed (`reply is not JSON`, `no text block`, `no choices`, `empty choices`), so a cut-off reply whose own words say "capacity" isn't called overloaded. `UpStatus` 429 is `relay_429`; 503 and 529 are overloaded.
  - `ErrorLine(Kind, Lab, N, Type)`: a random line of `cases.<Kind>`, falling back from `health_`, `down_` or `keytest_` + kind to the plain kind (the text after the first `_`); `""` and `NHOS: ERROR no line for <kind>` if neither exists.
  - `LabName(Prov)` (the persona's `name`), `ErrTypeText()` (the type, else `HTTP <upstream_status>`, else `no type`), `HealthFail(Kind, N)`.
  - `TrackActorAsk(Tag, User)`: `Ask` calls it for every `actor` ask; it keeps each tag's `show.scene` and `show.now` from the state JSON. A lower scene number than the last one means a new show, which clears the notes shown.
  - `BackstageNote(Tag, Ok, Error)`: `Deliver` calls it for every ask; for a failed actor ask it prints `NHOS: ERROR <kind> provider=<id> where=turn`, then `NHOS: NOTE <prov> scene <n> <line>` and the cue, or `NHOS: NOTE held <prov> scene <n>` for the same lab's second failure in a scene.
  - `ErrorTestPick(Tag)`, `ErrorTestFail(Tag, Prov)`, `FlushOne(Tag, User)`: in free mode `FlushLocal` hands each ask to `FlushOne`; with `error_test` set, the first actor ask of each new scene and `show.now` gets the test body through the real `HandleHttp` (pending entry with Try 1, so no retry), which prints `NHOS: ERROR TEST <name> <tag> provider=<id> expect=<kind>`.
- **Changed:** `ParseReply` keeps `upstream_status` in the new `UpStatus`; `HandleHttp`'s `GoDown` uses `ErrorLine("down_" + kind)` with the relay's `error.message` as the fallback, and prints `where=down`; `OnHealth` (`where=health`), `OnKeyTest`, `KeyTestResult` and `SetMode` (`where=keytest`) take their lines from `errors.json`. A key test whose reply is cut off or refused now passes (it proves the key works); before, an OpenAI `refusal` failed it. `LoadConfig` loads `errors.json` and `error_test`, and the `CLIENT ready` line shows `error_test=`. `Play via Relay needs the relay address in llm.json.` stays as it was (no approved line).
- `Tools/check_prompts.py --offline` also checks `test_replies` (each a known case, each with a body). `Docs/switches.example.json` has `error_test`.

### Unreal MCP rules found in this task

- `GetComponentByClass` is `Actor|GetComponentbyClass` in the DSL (`:self` the actor, `:ComponentClass` a class path); with a literal class its output is typed, so the component's own functions take it as `:self`.
- `remove_function_graph` removes an event dispatcher too.
- `get_node_type_pins` on a graph left nothing behind this time (`DownText` had its 3 nodes before and after), unlike T04's and T33's finding.
- A game window's `swift winid.swift <pid>` lists the menu bar as a layer-0 window wider than 800 too; pick the one taller than 500 as well.
- `http.server.HTTPServer` hangs before it listens on this Mac (`getfqdn` in `server_bind`), and a server in the Bash sandbox can't take connections; the stub relay (`Saved/T37/stub_relay.py`) skips `getfqdn` and runs outside the sandbox.
- `ObjectTools.set_properties` takes `values` as a JSON string; `get_properties` takes `instance` and `properties`.
