# T39 Art batch tool and asset list

Back to [the plan](../Plan.md). This task is done.

## Task

- **Model and effort:** Opus 5.5, high. A resumable batch over two paid APIs with a credit cap, and an asset list taken from the design doc.
- **Depends on:** nothing. The style test in `Docs/PropArt.md` passed.
- **Needs:** the Leonardo and Meshy keys in `Local/` (in place), about 15 Meshy credits. No editor.
- **Touches:** `Tools/art_gen.py`, new `Docs/PropArt/manifest.json`, new `Docs/PropArt/red_pill/`, `Docs/PropArt.md`, `Docs/tasks/T39.md`.
- **Why:** my request on 2026-11-15: a pipeline that generates every 3D asset of the new clay art direction. The style test passed (see "Test result" in [Docs/PropArt.md](../PropArt.md)): a Leonardo.ai image, then Meshy image to 3D, makes a model that fits. `Tools/art_gen.py` already does one asset at a time. This task makes it do a list.
- **Steps:**
  1. **Write the asset list,** `Docs/PropArt/manifest.json`, from the design doc's "Art Inspiration" tab (Costumes, Props and backdrops, The stage) and its "Stories" tab. One entry per asset:
     - `id` (snake_case, also its folder name in `Docs/PropArt/`), `kind` (`headpiece`, `prop` or `set`), `story` (card id, props only), `core` (false for a story's spare prop).
     - `prompt`: the subject in one or two sentences, then one shared style and framing suffix for every asset (take it from the horse head's prompt in `Docs/PropArt/plush_horse_head/leonardo.json`: modeling clay, stop-motion, matte with faint thumbprints, saturated slightly chalky colors, three-quarter view from slightly above, centered, plain light gray background, a single object). A headpiece is shown alone, as a hat for a small capsule-shaped robot, in a neutral color.
     - `meshy_model`: `meshy-7.1` for anything with detail; `meshy-6-lite` (15 credits with a texture) for plain shapes such as the pills, the bowling ball, the dino egg, the bucket, the rug, the envelope and the waiver.
     - `texture`: true for props and set pieces (Meshy's texture is the look), false for headpieces (each comes in several colors, so a clay material colors them). `polycount`: 15000 for `meshy-7.1`, 8000 for `meshy-6-lite`. `size_cm`: about 30 for props, about 25 for headpieces; set pieces as the doc says.
     - Status fields the tool fills in: `ref`, `task`, `credits`, `fbx`.
     - The plush horse head is already done: fill its status fields from its logs.
     - 13 headpieces, 28 props (6 spares; the bent spoon counts as core, because a want uses it) and 3 set pieces: the chandelier, a cherub for the proscenium and one horseshoe theater box with its balustrade.
  2. **Add the batch commands to `Tools/art_gen.py`,** all resumable (an asset with a done step is skipped) and all writing the status fields back into the manifest:
     - `batch-images --kind K [--ids ...]`: Leonardo, 4 candidates per asset into `Local/art/props/<id>/` (not git), a few assets at a time.
     - `pick ID N`: copies candidate N to `Docs/PropArt/<id>/ref.png`. The agent looks at the four and picks the clearest outline, as in the style test.
     - `batch-meshes --kind K [--ids ...] --max-credits C`: Meshy image to 3D for every asset with a `ref` and no `fbx`, up to 8 at once (Pro allows 10). Check the balance first, and never start a task that would pass `C`. FBX and thumbnail into `Docs/PropArt/<id>/`.
     - `sheet --kind K`: an HTML page of every thumbnail with its id, saved in `Local/art/`, so I can look at a whole kind at once.
  3. **Prove it on one asset:** the red pill, end to end (images, pick, mesh on `meshy-6-lite`, sheet). Check the balance before and after.
- **Done when:** the manifest lists every asset in the doc; the red pill's FBX is in `Docs/PropArt/red_pill/`; a second `batch-meshes` run skips it; the balance dropped by the credits in its log.
- **Budget:** 1,040 Meshy credits are left after the style test. This task uses about 15. The plan for the rest: headpieces 13 × 20 = 260 (T40), core props about 570 (T41), set pieces 3 × 30 = 90 (T42). That leaves about 100 for retries, so the 6 spare props are made only if credits are left, or after I buy more.

## Findings

- **Manifest shape.** Top level: `about`, `style_suffix`, `negative` (one negative prompt for every asset, taken from the horse head's, without its horse words, plus "numbers"), `leonardo_model` (`lucid-origin`) and `assets`. Each asset also has `images` (the Leonardo generation id) and `pick` (the candidate number) beside the status fields the task named (`ref`, `task`, `credits`, `fbx`). Headpieces carry `roles` (the roles and colors from the doc's Costumes table), which T47 can use.
- **Headpiece prompts** ask for "one neutral mid-gray clay color", not light gray, so the hat still stands out on the light gray background. They are shown alone ("nothing under it"), sized for a small capsule-shaped robot.
- **Set piece sizes are estimates.** The doc gives none, so the manifest says chandelier 180 cm, cherub 60 cm and theater box 300 cm. T43 sets the real scale when it places them.
- **Props the doc marks "none".** The Art Inspiration tab's table says engine shapes could build all but 5 of the 28 props (it names only the cursed ring, the dino plush, the plush horse head, the ransom bag and the ringing phone as needing a model). The task asked for all 28 in the list, so they are all there; T41 can skip any it builds from shapes.
- **Parody-safe subjects.** No prop prompt names a film or a trademark: the tin-can robot is a soup can with bolt eyes and a funnel hat, the glow-stick sword is a glow stick taped to a flashlight, and the safety waiver, milk carton and ransom bag ask for blank labels or wavy lines, not text.
- **Meshy costs (docs, 2026-11-15):** image to 3D on `meshy-7.1` is 20 credits for the mesh only and 30 with a 2K texture; `meshy-6-lite` is 5 and 15, and can't do 4K textures, `image_enhancement` or `remove_lighting`. `should_remesh` costs nothing extra. Pro runs 10 tasks at once; past that Meshy answers 429 `NoMorePendingTasks` with no Retry-After. The tool's cap uses these estimates and then counts what each task reports as `consumed_credits`.
- **Resuming.** `batch-meshes` writes a task's id into the manifest as soon as Meshy accepts it. If a run stops before the download, the next run downloads that task without paying again. A task that ends FAILED or CANCELED has its id cleared, so the next run starts it again.
- **Two runs at once.** Each status write reloads the manifest first, so two runs on different kinds (T40, T41, T42) don't overwrite each other's fields. Their commits still touch the same file, so commit one task's manifest changes at a time.
- **Red pill.** All four candidates were clean capsules; candidate 3 had the clearest outline and seam. Meshy took about a minute. On `meshy-6-lite` at 8,000 triangles the round ends show faint facets in the thumbnail. At about 30 px on the prop table that won't show, but a close-up would; `meshy-7.1` (30 credits) is the fallback for any lite prop that needs to look smooth up close.
- **Leonardo** still returns no `apiCreditCost` in the v2 reply, so the log has `null` for each generation's cost.
- **Sheets** use absolute `file:` links, so they open from anywhere on this machine, not on another one. The Claude app's browser pane shows local pages as a snapshot that can't load them; open the sheet in a normal browser.
