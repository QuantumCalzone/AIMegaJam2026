## Task

- **Model and effort:** Opus 5.5, high. Sound design by script without hearing the result, a real human voice to find, and a new function in `BPC_ShowAudio`.
- **Depends on:** T20 (`BPC_ShowAudio`, `SC_Voice`)
- **Needs:** editor + Unreal MCP running for steps 3 to 5, and the lock on `BPC_ShowAudio` (T71 changes it too, so one at a time). Steps 1 and 2 need no editor and can run as prep. My OK before any paid voice tool. No `BP_Show` or `WBP_Stage` lock, so it can run beside the editor chain.
- **Touches:** new `Tools/make_voices.py`, new `SourceAssets/Audio/voices/`, new `Content/NHOS/Audio/Voice/`, `Content/NHOS/Core/BPC_ShowAudio.uasset` (new `Syllable`), `Docs/Assets.md`, `Graphs/BPC_ShowAudio/` files for the graphs it writes, `Docs/tasks/T72.md`.
- **Why:** my request on 2026-11-15. Each robot gets its own way of speaking: gibberish sounds, one for each syllable, as in Animal Crossing, where a character "talks" in short sounds while its words type out. My own voice is a human trying to sound like a robot, so I am the odd one out by ear too. Today every line plays one short pluck, at a different pitch for each provider (T20). This task makes the sounds and one function that plays a sound. T73 types the lines out and calls that function for each syllable.
- **Steps:**
  1. **Four robot voices.** This step needs no editor.
     - Make one set for each provider (OpenAI, Anthropic, SpaceXAI and Meta, the `name` fields in `personas.json`). Each set has 8 to 12 short syllable sounds: about 0.06 to 0.15 s, mono, with a quick attack and a short tail. A run of them must sound like babble, not like beeps.
     - The voices differ in tone, not only in pitch: for example, a clean, bright chirp; a warm, round vowel; a crunchy, bit-crushed buzz; and a low, wobbly drone. Keep T20's pitch order (Meta lowest, then Anthropic, then OpenAI, with SpaceXAI highest). Match each voice to its persona in `personas.json`.
     - Make them with a script, `Tools/make_voices.py`: vowel sounds (formants) on a buzzy source, with a different source, filter or effect for each provider. Give it a fixed seed, so a second run makes the same files. The PC's Python has no numpy, but the standard library (`wave`, `struct`, `math` and `random`) is enough for clips this short. Kenney's Synth Voice 1 and 2 packs (CC0 robot-voiced words, in `Local/audio/kenney/` on the PC) are a fallback source of syllables.
  2. **My voice: a human doing a robot impression.** This step needs no editor.
     - Get 8 to 12 clips of a real person's voice saying robot syllables in a flat, careful monotone, such as "beep", "boop", "bzzt", "dee", "doo", "bop" and "kshh". Keep the small wobbles and breaths of a real voice, so it sounds a little off next to the robots. A synthesized voice won't do.
     - Look for sources in this order. First, a free recording whose license allows a game (CC0 or CC BY), for example on Freesound or Wikimedia Commons. Next, an AI voice tool whose terms allow game use, after my OK for any cost. Last, I record the clips myself: ask me with `AskUserQuestion`, and give me the list of syllables to say.
  3. **Files.**
     - Put the source files and the script's output in `SourceAssets/Audio/voices/<provider>/` and `SourceAssets/Audio/voices/me/`.
     - Import them into `Content/NHOS/Audio/Voice/<Provider>/` (`S_Voice<Provider>_00` and up, and `Me` for mine) on `SC_Voice`. Use T20's auto-import rule (in "Unreal MCP rules found in this task" in `Docs/tasks/T20.md`).
     - Add a row to `Docs/Assets.md` for each set: the script and its settings for the made sets, and the source and license for mine.
  4. **`BPC_ShowAudio.Syllable(Name, IsMe)`** plays one sound from the speaker's set.
     - The sound is picked at random, but never the same sound twice in a row. Its pitch changes at random by a small amount (about 6% up or down). It plays in 2D, like T20's sounds.
     - The function finds the set from the provider name, the same way `Blip` does (`StartsWith`). An unknown name gets a default set.
     - A new sound stops the speaker's previous sound, so fast lines don't pile up.
     - It prints nothing for each sound, because a show will play thousands of them. T73 adds a count to each line instead.
     - Leave `Blip` and its call as they are. T73 replaces them.
  5. **Levels.** Set the voices about as loud as T20's blip (0.3 effective), and even across the five sets. The script can measure each clip's peak and RMS level and print them.

## Findings

### T72: what was built (2026-11-15, Mac)

- **How each robot voice is made** (`Tools/make_voices.py`, its docstring has the rest). Each syllable is a source at a pitch that moves along a short contour, through three formant resonators (a vowel that glides to a second vowel), with an optional consonant in front (a noise burst for b/d/t/k, a hiss for s/z/ks, a hum for m/n), a 3 to 8 ms attack and a 20 to 40 ms tail. The base pitches are T20's blip pitches × 175 Hz, so T20's order holds.
  - **OpenAI, a clean, bright chirp:** many soft sine harmonics (no buzz), front vowels (ee, ih, eh, ae), formants × 1.15, a calm upward glide of 12 to 30%, a breath of air, a +6 dB shelf at 2 kHz and a faint 23 ms echo. Calm hype about the future.
  - **Anthropic, a warm, round vowel:** a smooth glottal pulse, rounded vowels (oh, oo, ah, aw), a low-pass at 2.2 kHz, a 9 Hz flutter of 1.8% with a little jitter (nervous), and an end that falls 7 to 14% (a sigh).
  - **SpaceXAI, a crunchy, bit-crushed buzz:** a square and saw source, formants × 1.2, driven into clipping, crushed to 3 bits at 7.35 kHz, with jumpy pitch steps or fast downward zips, and hissy onsets (z, ks, k, t). Loud and chaotic.
  - **Meta, a low, wobbly drone:** a dark saw with a nasal hum at 260 Hz, formants × 0.9, a low-pass at 1.6 kHz, a flat monotone with an 8 Hz vibrato of 7% and a matching tremolo. Stiff, trying hard to sound human. (A 5.5 Hz vibrato didn't finish one wobble inside a 0.12 s syllable, so it is 8 Hz.)
- **The sets differ in tone, not only in pitch** (means from the script's numbers; spectral centroid is the "brightness", flatness the "noisiness", and "pitch moves" the range of pitch inside one clip):

  | Set | Clips | Length s | Pitch Hz | Pitch moves | Centroid Hz | Flatness | <300 Hz | 300 Hz-1 kHz | 1-3 kHz | 3-8 kHz | >8 kHz |
  |---|---|---|---|---|---|---|---|---|---|---|---|
  | OpenAI | 10 | 0.082-0.119 | 227 | 35% | 2438 | 0.001 | 3.0% | 12.8% | 54.0% | 30.2% | 0.0% |
  | Anthropic | 10 | 0.091-0.127 | 159 | 10% | 485 | 0.000 | 8.6% | 87.3% | 4.0% | 0.0% | 0.0% |
  | SpaceXAI | 11 | 0.076-0.113 | 307 | 24% | 1106 | 0.015 | 11.6% | 70.3% | 11.0% | 5.8% | 1.4% |
  | Meta | 10 | 0.101-0.145 | 126 | 11% | 408 | 0.000 | 46.5% | 50.4% | 3.1% | 0.0% | 0.0% |
  | Me | 12 | 0.215-0.250 | 203 | 18% | 642 | 0.000 | 48.2% | 41.2% | 5.5% | 5.1% | 0.0% |

  OpenAI is the only bright one (84% of its energy above 1 kHz), Anthropic sits almost all in the vowel band, SpaceXAI is the noisiest (15 times the others' flatness, and the only energy above 8 kHz), and Meta is the low one (46% under 300 Hz). The first draft's "bright chirp" had a centroid of 365 Hz and 68% of its energy under 300 Hz; less of the dry source and more of the upper formants fixed it.
- **Levels.** Every clip, mine included, is set to the same weighted loudness, -25.5 dB (an RMS through a high-pass at 100 Hz and a +4 dB shelf above 1.5 kHz), with its peak under -1 dBFS (the peaks came out at -9 to -18 dBFS). T20's talk blip file (Kenney's `pluck_001.ogg`, decoded with `afconvert`) measures -25.6 dB the same way, so the voice waves take the blip's own settings: volume 0.6 under `SC_Voice` (0.5), 0.3 effective. `python Tools/make_voices.py --measure <wav>...` prints any file's numbers. Plain RMS differs by set (OpenAI -28.5 dB, Meta -24.6 dB), because the weighting counts highs as louder.
- **My voice.** No free recording fit: Freesound's CC0 and CC BY results held synthesized robot voices, and the one real voice ("boop boop booooa.wav" by Reitanna, CC0) had only three boops. My person recorded one 30.5 s take (mono, 44.1 kHz) saying beep, boop, bzzt, dee, doo, bop, kshh, blip, zap, bleep, dah, wub, then five more. It is kept as `SourceAssets/Audio/voices/Me/source/recording.wav`. `make_voices.py --me <take> --first 12 --max-len 0.25` finds syllables by gaps of 150 ms of quiet (a threshold of 3 × the noise floor or 4% of the loudest, whichever is higher), drops pieces under 60 ms or 20 dB below the loudest syllable (a breath after "doo"), keeps a 15 ms lead-in and a 60 ms tail, cuts at 0.25 s with a 40 ms fade, high-passes at 80 Hz and sets the same loudness. It found 17 syllables and keeps the first 12, so `S_VoiceMe_00` to `_11` are the twelve words above, in that order ("kshh" is `_06`, the one with the 3.5 kHz centroid). The first four were said more softly (about 13 dB under the rest), so leveling raised their room noise more. No AI voice tool was used, and nothing was paid for.
- **The assets.** 53 sound waves: `Content/NHOS/Audio/Voice/OpenAI/S_VoiceOpenAI_00` to `_09`, `Anthropic/..._00` to `_09`, `SpaceXAI/..._00` to `_10`, `Meta/..._00` to `_09`, `Me/S_VoiceMe_00` to `_11`. Each is on `SC_Voice` at volume 0.6, mono, not looping, imported with T20's auto-import (copy the wav into `Content/`, delete the copy once the asset is there). The two editor settings that rule needs were set back to true afterwards.
- **`BPC_ShowAudio.Syllable(Name, IsMe)`** (`Graphs/BPC_ShowAudio/Syllable.txt`). The slot: me (`IsMe`) is 4; otherwise the name's start picks OpenAI 0, Anthropic 1, SpaceXAI 2 or Meta 3, as `Blip` does; any other name is slot 5 and uses the OpenAI clips. It rolls a clip among the set's count minus one and steps over the slot's last clip (`VoiceLast`), so a clip never plays twice in a row for a speaker. It calls `StopVoice(K)`, which stops the slot's last audio component if it is still valid (`VoiceComp`), then `SpawnSound2D` with the pitch at random in 0.94 to 1.06 and keeps the new component. No print. New variables: `VoiceSounds` (sound array), `VoiceComp` (audio component array), `VoiceLast` (int array), `VoicePick` (int). The two arrays are sized to 6 on the first call.
- **`LoadVoices`** fills `VoiceSounds` with the 53 sounds on the first call (`Graphs/BPC_ShowAudio/LoadVoices.txt`; the set order, and so `Syllable`'s starts 0, 10, 20, 31, 41 and counts 10, 10, 11, 10, 12, is in its comment). A clip added to a set needs a line there and new starts and counts in `Syllable`. The graph's 53 object literals are hard references (`get_dependencies` of `BPC_ShowAudio` lists all 53), so a build cooks them.
- **Check (PIE, Test for Free, `mode: free`, autoplay off):** `Saved/T72/syl_test.py`, run with `py` from the console box, called `Syllable` 8 times each for OpenAI, Anthropic, SpaceXAI, Meta, me and "Robot", and read back `VoicePick` and the slot's sound after each call. Each speaker got only its own set's clips, with no repeat in a row (48 calls), "Robot" got OpenAI clips, and afterwards exactly 6 voice components were playing in the whole world, one per slot, at pitches from 0.946 to 1.041. No `LogScript` warning and no Python warning.
- **Not checked:** how anything sounds (whether a run of syllables reads as babble and not beeps, whether the voices fit their personas, whether my clips sound "a little off" next to the robots, whether the hard stop of the last syllable clicks). My clips are 0.22 to 0.25 s, about twice the robots'; T73's syllable rate decides whether they overlap or get cut. No show was played: nothing calls `Syllable` yet (T73 does), and nothing on screen changed.
- **Switches:** none changed. `spare_human` was already true in `Local/switches.json` when this task started.

### Unreal MCP rules found in this task

- **A default set on a component class's CDO after a compile doesn't reach the component's template in a Blueprint that's already open.** `VoiceSounds`, set on `BPC_ShowAudio`'s defaults with `ObjectTools.set_properties` after the compile that added it, stayed empty on `BP_Show`'s `Audio` component in PIE ("Attempted to access index 1 from array 'VoiceSounds' of length 0"). Fixing it would mean saving `BP_Show`. Filling the array in a graph on first use avoids the template entirely.
- **An object literal works on `Utilities|Array|Add`'s Item pin of a typed array variable:** `(add (V VoiceSounds) "/Game/.../S_X.S_X")` reads back with the path kept.
- **Calling a component's Blueprint function in PIE from Python:** `unreal.get_editor_subsystem(unreal.UnrealEditorSubsystem).get_game_world()`, `unreal.GameplayStatics.get_all_actors_of_class(world, unreal.load_object(None, "/Game/NHOS/Core/BP_Show.BP_Show_C"))`, `actor.get_component_by_class(<BPC class>)`, then `comp.call_method("Syllable", ("OpenAI", False))`. A Blueprint variable reads with `comp.get_editor_property("VoicePick")`. The script runs with `py "<file>"` typed into the editor's `Cmd` box (`SlateInspector.Type` with `submit`), and its `unreal.log` lines land in the editor log, which on this Mac is `~/Library/Logs/Unreal Engine/AIMegaJam2026Editor/AIMegaJam2026.log`, not `Saved/Logs/`.
- **`AssetTools.read_file` reads only `.csv`, `.html`, `.json`, `.md`, `.py` and `.txt`.** A long DSL text can go to the editor as a `.txt` under `Saved/`, read by `read_file` inside a `ProgrammaticToolset` script and passed to `write_graph_dsl`, which keeps it out of the tool call.
- **macOS `afconvert` decodes `.ogg`** (`afconvert -f WAVE -d LEI16 in.ogg out.wav`), so a standard-library script can measure the game's Kenney sounds.
