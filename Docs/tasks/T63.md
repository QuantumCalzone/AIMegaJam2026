# T63 My turn sends a built action and a spoken line

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** the input spec in [T62.md](T62.md) ("The input spec", above all "What happens after sending"). Clicks make my action and the speech field makes only speech. The action goes straight into the shared log with no LLM, and the input LLM only fixes the spelling of my line. Today the input LLM turns my whole typed line into up to two actions and speech.
- **Steps:**
  1. **The design doc first.** The input LLM's prompt (step 3) changes in the doc's Bot Prompts tab first, after my OK. T62 put the input spec in the Rules tab: check that it still matches what this task builds, and propose a fix if it doesn't.
  2. **One call for my scene turn.** `BP_Show.SendHumanTurn(Verb, Item, Target, Line)` replaces `SendHumanTurn(Line)`. Verb is move, look, grab, throw, give, around (Look around) or none (No action). Item and Target are prop, place and Player names, as T62's functions use them.
     - **The action:** check it with T62's `CanDo`. A failed check becomes a look around, the fallback a bot gets. Write it with the `does_templates` wording ("grabs the rose", "stands still" for none). It goes into the shared log as my `does`, in the same form as an AI's. No LLM sees it.
     - **The line:** `ResolveMentions`, then the input LLM (step 3), then `CapWords`. The reply's `speech` becomes my `says`. Its `actions` are ignored.
     - **The wait:** the input LLM gets `spelling_wait` seconds, from a new `Content/NHOS/Data/input.json` (start at 4; T66 adds the timers there). A `spelling_wait` of 0 skips the call. If the call fails, is refused or takes longer, my line goes as typed: `ScrubLabels` on it, so no provider name reaches the AIs, then `CapWords`, and print `NHOS: SPELLING skipped <why>`. A reply that comes late is dropped. My turn never stalls on it.
     - Print `NHOS: HUMAN <verb> <item> <target> says=<line>` with what went into the log, `-` for an empty field.
     - Until T64 builds the builder, the input box sends its text as the line with Verb none, so the game stays playable.
  3. **The input LLM fixes spelling only.** Rewrite `prompts.json` `input` and `asks.input`:
     - The player's text is only speech. Fix misspelled words and change nothing else: not the wording, word order, tone, caps, emoji, slang or punctuation.
     - Keep every @ mention as written.
     - Keep the names rule: a screen name, or the name of that lab's company, models or leader, becomes that actor's Player name. A provider name in my line would show the AIs who is human.
     - Never make an action: "I throw the rose" stays speech. `actions` is always empty, and `vote` and `reason` are "".
     - Cap at 15 words. In "free talk", an empty or "pass" text sets `pass`.
     - Drop the old rules for actions, quotes and "say hello to the queen becomes Hello". `InputState` drops `places` and `props`. Update the `_readme` (the input LLM's fields).
  4. **Every other line of mine takes the same path.** `SendHumanTalk` (Free Talk), `SendHumanReact` (my reactions), `SendHumanVote` (my vote's reason) and T58's last word send speech through step 2's line path, with the same wait and fallback. None of them makes an action.
  5. **Autoplay.** In a scene turn, my seat picks a random action from T62's `ItemsFor` and `TargetsFor` (sometimes Look around or No action) and says its canned line. `autoplay.json`'s scene lines become speech only. Update its `_readme`.
  6. **The checker.** `Tools/check_prompts.py` checks `input.json`, and its input cases test spelling only:
     - "teh robto is hungyr" gives "the robot is hungry".
     - "tell open ai to calm down" gives "tell Player 1 to calm down" when OpenAI is Player 1.
     - "I throw the rose at @Player 2" keeps its words and its mention, and has no actions.
     - A line of slang and emoji comes back the same.
     Run `--offline`, `--relay --free`, and, after my OK, a paid `--ask input` run (a few cents).
- **Done when:**
  - The three checker runs pass.
  - A free autoplay show in a game window reaches `NHOS: SHOW END` with no `LogScript` line, and each of my scene turns prints `NHOS: HUMAN` with an action that T62's check allows.
  - In PIE (Test for Free, autoplay off), a typed "I grab the rose" goes into the log as my speech with "stands still", and nothing is grabbed.
  - With `spelling_wait` set to 0 for one turn, my line goes as typed and prints `NHOS: SPELLING skipped`. Set it back to 4.
