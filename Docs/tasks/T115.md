# T115 The game gets its own icon

Back to [the plan](../Plan.md). Done on 2026-11-20: its entry is under "Done" there.

## Task

- **Model and effort:** Opus 5.5, high. A design judged by eye at 16 px, and a packaged build to check it.
- **Depends on:** none. Run it on the PC: its check is a Windows build. It needs the editor only for a render of the costume, and changes no asset.
- **Needs:** the engine, to package a Windows build (about 6 minutes); my pick of the icon; my OK before any paid generation.
- **Touches:** `Build/Windows/Application.ico` (new), the Mac icon where UE 5.8 reads it, `.gitattributes` (only for an `.icns` rule), `Config/Default*.ini` (only if the icon needs a setting), new `Docs/Art/Icon/`, `Docs/Assets.md`, `Docs/tasks/T115.md`.
- **Why:** my request on 2026-11-19, with the itch.io media (T113): the game should have its own icon. The packaged game still shows Unreal's default icon on its `.exe`, its window and its taskbar button. The itch.io page has no icon of its own (its thumbnail is the cover, T113), so this icon is the one on the player's computer.
- **What makes it good:**
  - **One bold shape that reads at 16 × 16.** The hook in one picture is a good start: the costume's teal cardboard head, with the person's eyes peeking through the slots and the drawn smile. A better idea is welcome.
  - **The game's own look.** Make it from an in-engine render of the game's own model (a close-up in flat, bright light), simplified and cleaned up in 2D, on a solid color from `UIStyle`. Ask me before any paid generation.
  - **Readable on light and dark.** The taskbar and Explorer can be either.
- **Steps:**
  1. **Find where the icons go.** Find where UE 5.8 reads each platform's icon for a packaged game: the engine's own default files and the project overrides under `Build/<Platform>/`. Check that this Blueprint-only project's build picks them up (packaging compiles a small game program here, so the Windows `.ico` should be built into the `.exe`). Write what you find under "## Findings".
  2. **Design.** Make three candidates. Look at each at 16, 32, 48 and 256 px, on a light and a dark background. Show me all three and ask me to pick one.
  3. **Make the files.** Keep the source at 1024 × 1024, the candidates and how they were made in `Docs/Art/Icon/`. Write `Build/Windows/Application.ico` with the sizes Windows uses (16, 20, 24, 32, 40, 48, 64, 128 and 256). Make the Mac icon where 5.8 reads it too; if it is an `.icns` file, add an LFS rule for it to `.gitattributes` first. If an icon needs a project setting, edit `Config/Default*.ini` with the editor closed.
  4. **Check.** Package a Windows build into `Packaged/` (the command is in `Docs/Builds.md`). Explorer shows the icon on the `.exe`, and the running game shows it on its window and its taskbar button. The Mac icon can be checked only in a Mac build: write it under "## Findings" as unchecked, for the next Mac build (T92).
  5. **Record it.** Add the icon to `Docs/Assets.md`: what it is, what it was made from and how.
- **Done when:** `Build/Windows/Application.ico` is in git with every size, and a packaged Windows build shows it on the `.exe`, the window and the taskbar button; the Mac icon file is where 5.8 reads it; the source and the candidates are in `Docs/Art/Icon/`; and I have picked the icon.
- **Result:** done on 2026-11-20. The game has its own icon, my pick of six: a grinning person pushes the costume's teal box head up and off with one striped sleeve and garden glove, and winks, on a UIStyle Red (`#C8202F`) tile with an ink rim ("2 Tilt", `Docs/Art/Icon/icon_sheet.png`). `Build/Windows/Application.ico` holds 16, 20, 24, 32, 40, 48, 64, 128 and 256 px (16 to 32 hand-placed pixels). A packaged Windows build shows it on the `.exe` in Explorer, the window's title bar and its taskbar button (`Docs/Art/Icon/check_windows.png`). The Mac icon is the `AppIcon` set in `Build/Mac/Resources/Assets.xcassets`, unchecked until the next Mac build. Drawn by our own script from an in-engine render of the costume, with no paid generation; `Docs/Art/Icon/README.md` has how, and `Docs/Assets.md` has its row.

## Findings

- **Where UE 5.8 reads each icon (step 1).**
  - **Windows:** `Build/Windows/Application.ico` in the project, else the engine's `Engine/Build/Windows/Resources/Default.ico` (`GetWindowsApplicationIcon` in UnrealBuildTool's `UEBuildWindows.cs`). It goes into the `.exe` as resource 123, `IDICON_UEGame` (`Engine/Build/Windows/Resources/Default.rc2`), and the running game loads that resource for its window class (`WindowsPlatformApplicationMisc.cpp`), which gives the title bar and the taskbar button. This project compiles its own game program (the `HttpBlueprint` and `JsonBlueprintUtilities` plugins), so UnrealBuildTool builds the icon into `Binaries/Win64/AIMegaJam2026.exe`. The packager also writes it into the bootstrap `AIMegaJam2026.exe` at the build's root (`WinPlatform.Automation.cs`). Its content-only step, which patches the icon into a prebuilt `UnrealGame.exe`, doesn't run for this project. No project setting is needed, and `Config/` is unchanged.
  - **Mac:** UE 5.8 builds Mac apps through a generated Xcode project. It uses the project's `Build/Mac/Resources/Assets.xcassets` in place of the engine's (`ProjectOrEnginePath` in `XcodeProject.cs`), and Xcode compiles its `AppIcon` set as the app icon (`ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`). The packager would also copy a `Build/Mac/Application.icns` into the app (`MacPlatform.Automation.cs`), but nothing points the app at it, so there is no `.icns` and no new LFS rule: the set is PNGs (already in LFS) and two `Contents.json` files.
- **Round 1 wasn't the idea.** Three versions of the box head alone (an ink tile with a gold rim, a gold tile, the face alone; `Docs/Art/Icon/round1/`) read well at 16 px. My person answered "Make it a human pulling off the robot headpiece." Round 2 had three versions of that: Lift, Tilt and Peek (`round2/`). My person picked Tilt.
- **The person under the box had no design.** No doc says what the human in the costume looks like, and the game never shows them. The icon draws one: warm skin (`#E3A87C`), dark brown hair standing up with static from the box, a wink and an open grin. If the game ever shows the person, start from this or change the icon to match.
- **Below 32 px, shapes need hand-placed pixels.** Round 1's round eyeballs and the vector art of round 2 turned to gray mush at 16 to 32 px, and at 32 px the grin's ink and the chin's outline read as a beard. 16, 20, 24 and 32 px are pixel grids in `RevealArt.cs` (the box stepped at a clean 1:2 slope). 40 and 48 px use the vector with fewer details. Windows draws 16 px in the title bar and Explorer's lists, 24 px on the taskbar at 100% scale, and 32 px at 125%.
- **The check (step 4).** The build was packaged from the task's worktree into its own `Packaged/` (`BuildCookRun`, 2 minutes with warm caches, 0 errors), with `{"analytics": "off"}` in its `Local/switches.json`. Both `.exe` files carry every size of the icon (`PrivateExtractIcons`), and the shell's icon for the root `.exe`, the one Explorer draws, is the new one at 32 and 16 px (`SHGetFileInfo`). The running game's title bar shows it at 16 px and its taskbar button at 24 px (a `PrintWindow` capture of the window and a screen capture of the taskbar: `Docs/Art/Icon/check_windows.png`). The window class holds the 32 and 16 px icons. The game reached its title screen and was closed. The build wasn't zipped or uploaded, so the secrets check didn't run.
- **The Mac icon is unchecked.** For the next Mac build (T92's steps, or T120's build): check that Finder, the Dock and Cmd-Tab show the icon, not Unreal's. The Mac set follows Apple's grid (an 824 px body with a soft shadow, `icon_mac_1024.png`). macOS 26 and later may still put an icon from an older Xcode in a gray rounded square. If it does, the Mac build's Xcode needs an Icon Composer icon, which this PC can't make.
- **Rendering from a second editor:** a second editor opened from the worktree with `-ModelContextProtocolPort=8011` framed the costume robot in `L_Stage` and saved nothing. The first `CaptureViewport` after a big camera move returned the old frame. A second call with the same transform got the right one.
