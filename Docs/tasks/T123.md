# T123 The web, part 1: a spike on the full UE 5.9 release

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** my verdict on T112 (2026-11-20): no Android release, but web builds are a go. UE 5.9's web target (WebAssembly and WebGPU, on the mobile renderer) was a preview in November 2026, with parts Epic called prototypes. This spike tries it on the full release, before T124 to T128 change anything in the game. T112's [Docs/Mobile/README.md](../Mobile/README.md) has the look on the mobile renderer and the web table this spike checks.
- **Rules:**
  - Work in a throwaway copy of the project outside the repo folder (for example `C:/Users/Personal/Projects/NHOS_web`, made like T112's copy: `git worktree add --detach` from the repo folder). Only that copy moves to 5.9. Never open the repo folder's project in 5.9: assets saved in 5.9 don't open in 5.8.4.
  - Download nothing (UE 5.9, emsdk, anything else) without my OK, and give the size when you ask.
- **Steps:**
  1. **Read first.** T112's findings and `Docs/Mobile/README.md`; Epic's web platform notes for the full 5.9 release (what changed since Preview 2: engine build, Blueprint-only packaging, memory, browsers, files, HTTP, hosting, known issues).
  2. **Set up.** After my OK, install UE 5.9 beside 5.8.4 and emsdk at the version Epic names. Make the copy and convert it to 5.9.
  3. **Package and play.** Package the copy for the web and serve it locally as Epic's notes say. In Chrome, play a free show (Test for Free) from the title to the end screen. Screenshot the title, Scene Prep, a scene turn, Free Talk, The Cut and the end screen beside the same shots on the desktop game, as T112 did. Note the frame rate (`stat unit`), the memory, the size of each file and of the whole build, and the time to the title on a first and a second load.
  4. **What the game needs from a browser.** Check each, and write what happens:
     - The relay: `GET /health` and `POST /event` from the page. They should fail on CORS until T124; note the page's origin and the request headers, for T124.
     - Typing in the chat box and the key screen; keyboard play (T34); the hover cards (T85).
     - Sound after the first click.
     - Files: does the first-show flag (`Local/progress.json`) or `SG_Player` survive a page reload? Can the game read `Content/NHOS/Data/*.json`?
  5. **The tiers.** Try the web's rendering tiers (Mobile Forward, Mobile Deferred, the desktop tier if it is still there). Do T112's look issues (dark stalls, no robot shadows, touch joysticks) still show?
  6. **Write the verdict for me.** Go or no-go for T124 to T128, each with what this spike changed in its steps (edit their files). And the choice: move the whole project to 5.9 (every machine, a task of its own), or keep 5.8.4 on `dev` and build the web from a 5.9 copy for each web release.

  2. I gave my verdict and my choice of 5.9 or a web copy.
  3. The repo folder has no changed asset, and the project is still on 5.8.4 (`git status`, `EngineAssociation`).
  4. No key is in git or in this chat.
