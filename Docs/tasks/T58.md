# T58 Last word: a reply for anyone @-mentioned in the final round

Back to [the plan](../Plan.md). Done on 2026-11-15; its entry there is cut down to its title line and this link. The build sheet is [T58-build.md](T58-build.md).

## Task

- **Model and effort:** Opus 5.5, high. A new step between Free Talk and The Cut, with a new ask and a human turn.
- **Depends on:** T57 (the lock on `BP_Show`, and Free Talk as it leaves it), T30 (the line queue)
- **Needs:** editor + Unreal MCP running, Test for Free for the PIE shows, the relay for a `--relay --free` check, my OK before the relay is deployed again (a new free-mode phase).
- **Touches:** `Content/NHOS/Data/prompts.json` (new `asks.last_word`, `game`), `Content/NHOS/Data/free_mode.json`, `Content/NHOS/Data/autoplay.json`, `Tools/check_prompts.py`, `Content/NHOS/Core/BP_Show.uasset` (`NextTalker`, `EndFreeTalk`, new functions, `ComputePrompt`), `Relay/`, `Graphs/` files for the graphs it writes, `Docs/tasks/T58.md`.
- **Why:** design change 9 of 12 (2026-11-15). Anyone who is @-mentioned in the final Free Talk round gets one reply before the vote. Today an actor accused in the last round goes to the vote with no answer. The rule is in the design doc's Rules tab ("Free Talk", Last word).
- **Steps:**
  1. **Who gets a last word:** every actor on stage whose Player name follows an @ in a line of the final round, by someone else. One reply each, in a random order. A mention inside a last word gives no further last word.
  2. **`BP_Show`:** after the final round's last speaker (`NextTalker`, before `EndFreeTalk`), run the last words one speaker at a time, like a Free Talk round, through the line queue. Put the new logic in its own functions, for example `StartLastWords` and `PlayLastWord`. Each reply goes in the shared log with `when` "scene n, last word". With nobody mentioned, the step is skipped. Print `NHOS: LASTWORD <id> scene=<n>` for each, and `NHOS: LASTWORDS DONE scene=<n> entries=<n>`.
  3. **My last word:** if I was mentioned, the input row asks me for one line (`ComputePrompt`: "You were named. One last line before the vote."), with Pass on. It goes through the input LLM as a Free Talk line. With autoplay on, it uses a new `last_word` list in `autoplay.json`.
  4. **`prompts.json`:** a new ask, `asks.last_word`: answer the actor who named you, one line, no actions, a pass allowed. `game`'s "How a show works" names the last word. Update `_readme` (`when` values).
  5. **`free_mode.json`:** a `last_word` phase, placed before `free_talk` in the match order, with a few lines. The relay bundles this file, so ask me before you deploy it again.
  6. **`Tools/check_prompts.py`:** `last_word` joins `ACTOR_ASKS`, with a sample state.
  7. **Check:** `--offline` and `--relay --free` pass. Give a few `free_talk` lines in `free_mode.json` an @ mention (`@{actor}`), so free shows have mentions in the final round. In a free autoplay show, every actor mentioned in the final round gets one last word before the vote (`NHOS: TALLY`), and a scene whose final round has no mention skips the step. My canned final-round line stays "pass", because T57's check uses it.
- **Done when:** the check passes, and Claude plays one show by hand, gets named in the final round and gets its reply before the vote.
- **Result:** done on 2026-11-15. After the final Free Talk round, every actor on stage that someone else named with @ in that round gets one reply before the vote, one at a time in a random order, under the header "LAST WORD: SCENE n". A mention of a cut actor, or a mention inside a last word, gives nothing; with nobody named, the vote follows at once. My own last word opens the input row ("Last word. You were named. One last line before the vote, or press Pass.") and goes through the input step like a Free Talk line. The bots answer the new `asks.last_word`; free mode, in the game and the relay, has a `last_word` phase, and two of its Free Talk lines now open with an @ mention.

### Unreal MCP rules found in this task

- **`(return x)` in `write_graph_dsl` makes no output pin.** Add the output first with `add_function_param` (`param_name` `ReturnValue`, `param_type` `string`, `input_param` false), then write the graph; a caller's `bind` on the function fails with "expression produced no output pin" until then.
- **`write_graph_dsl` needs named pins on calls to the Blueprint's own functions** (`(CallFunction|ActorState :Seat ... :AskKey ... :Now ...)`, `(Class|BPCLLMClient|Ask :self ... :Tag ... :Role ... :System ... :User ...)`). The positional form that `read_graph_dsl` prints fails with "Could not connect pin ... to self".
- **`AssetTools.read_file` and `write_file` take `file_path`**, an absolute path. `write_file` accepts only `.csv`, `.html`, `.json`, `.md`, `.py` and `.txt`, so a screenshot's base64 goes in a `.txt` and is decoded outside the editor.
- **`AssetTools.save_assets` takes `asset_paths`** (a list of object paths).
- **The PIE floating window can open maximized,** so check a screenshot's size before calling it 1600 × 900.
- `Local/switches.json` is back to `autoplay`, `spare_human` and `fast_lines` false, `EditorPerformanceSettings.bThrottleCPUWhenNotForeground` is back to true, and every game window is closed.
