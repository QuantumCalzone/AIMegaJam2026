# T68 Analytics, part 2: the game sends its events

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** the game half of analytics; [T67.md](T67.md) has the why and the relay half. Every mode reports, Test for Free included, because the relay never sees free shows or players with their own keys. A player can turn it off, and the dev machines never pollute the data.
- **Steps:**
  1. **A player id.** A new SaveGame class, `Content/NHOS/Core/SG_Player.uasset`, in slot `player`, holds `PlayerId` (a new GUID with no dashes, made on the first launch), `FirstSeen` (the UTC date), `Launches` (plus one each launch) and `AnalyticsOn` (true at first). It is anonymous: nothing from the Epic account, the machine or the keys.
  2. **`BPC_Analytics`,** a new component on `BP_Show` (`Content/NHOS/Core/BPC_Analytics.uasset`). Its one entry point, `Send(Event, Fields)`, posts T67's body to `<relay>/event` (the relay address in `llm.json`) with the same HTTP nodes `BPC_LLMClient` uses. It never waits on the answer, and a failure only prints `NHOS: ANALYTICS fail <event>`. Every send prints `NHOS: ANALYTICS <event>` for the checks. `session` is the show's session id (`BPC_LLMClient.Session`), or one id made at launch for events before a show. `build` is a version string in `llm.json` (a new `build` field). `mode` is the mode in play.
  3. **When it sends.** Each caller adds one node:
     - `launch` (`launches`, `first_seen`): when the title screen opens (`WBP_Title`)
     - `mode`: when a mode is picked (`BPC_LLMClient.SetMode`, after it succeeds)
     - `show_start`: when the show starts
     - `phase` (`phase`, `scene`): at the start of each phase in `BP_Show`: each Scene Prep, scene turns, Free Talk, the last word, the Cut's vote, reactions. Read `RunCue` and the cue graphs first, and add the call where every phase passes, not once per phase graph.
     - `show_end` (`result`, `reason`): at the end screen, with `BP_Show.WinReason`
     - `error` (`kind`): when the unavailable screen or a backstage note shows, with `BPC_LLMClient.ErrorKind`'s case
     - `calls`: `BPC_LLMClient` counts each ask per provider and model: calls, failures, and tokens in and out from the reply's usage (Messages: `usage.input_tokens` and `output_tokens`; Chat Completions: `usage.prompt_tokens` and `completion_tokens`; 0 in Test for Free). It sends one `calls` event per provider at each phase start and at the end, then clears the counts. A player who quits mid-show still leaves the counts up to the last phase. The game can't send anything when the window closes.
  4. **Drop-off needs no quit event.** A show's drop-off point is the last `phase` it sent. Write that in the README section T67 added.
  5. **Turning it off.**
     - **Builds only (my call, 2026-11-15):** nothing done in the Unreal Editor counts. The game sends events only when it runs as a packaged build: PIE and game windows started from the editor send nothing, whatever the other settings say. The one exception is the `analytics` switch set to `test`, which sends from the editor too, every event marked `"test": true`, so this task's and T69's checks still work. Find a check that is true only in a packaged build (`Is Packaged for Distribution` is true only for Shipping, and the jam build is Development) and write it under "## Findings".
     - **Our own machines:** print the player id once at launch, `NHOS: ANALYTICS player <id>`, so we can add each of our machines' ids to `ignore_players` in `Local/stats.json`; the report leaves those players out (T67).
     - **For players:** a small line on the title screen, "Sends anonymous play stats" with an on/off toggle, styled from `UIStyle` and reachable by keyboard as T33 left the title screen. It sets `AnalyticsOn` in the SaveGame. Turning it off sends one last `analytics_off` event, then nothing.
     - **For us:** a new switch, `analytics` in `Local/switches.json`: `off` sends nothing, `test` marks every event `"test": true`, and a missing switch or `""` sends normally. `Docs/switches.example.json` gets `"analytics": "off"` and a line in its `_readme`. Set it in this machine's `Local/switches.json` too, so agents' test shows stay out of the data. An autoplay run sends only when the switch is `test`.
  6. **The docs that say free mode makes no network call:** CLAUDE.md ("Test for free"), `Relay/README.md` (free mode), the `_readme` in `llm.json` and in `Docs/switches.example.json`. They now say that free mode makes no LLM call, and sends only analytics events unless they are turned off.
  7. **The itch page.** `Docs/ItchPage.md` gets a short privacy line: what is sent, that it is anonymous, and how to turn it off.
- **Done when:**
  - A free autoplay show in a game window, with `"analytics": "test"`, prints `NHOS: ANALYTICS launch`, `mode`, `show_start`, a `phase` for every phase, `calls` and `show_end`, and reaches `NHOS: SHOW END` with no `LogScript` line. `python Tools/analytics_report.py --test` shows that show in every heading.
  - With `"analytics": "off"`, a free show prints no `NHOS: ANALYTICS` line except `NHOS: ANALYTICS off`.
  - In PIE (Test for Free, autoplay off, a 1600 × 900 window), a screenshot shows the title screen's stats line and toggle. Turning it off and starting a show sends nothing after `analytics_off`.
  - A second launch shows `launches` 2 for the same player id.
  - Set `analytics` back to `off` and autoplay back to false when done.

**Where the build differs from the sheet:**
