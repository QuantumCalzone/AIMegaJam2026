## Task

- **Model and effort:** Opus 5.5, high. Props become data-driven meshes across the prop actor, the stage director and the state the AIs read.
- **Depends on:** T44 (the cards' props), T43 (the prop models and their fit)

- **Why:** since T44, each card lists four props of its own, and T43 made a model for each. Today eight shape-built `BP_Prop` actors (T19) serve every story, and the state the game sends the AIs lists the same eight in `set.props`.
- **Steps:**
  1. **`Content/NHOS/Data/props.json`:** for each prop name on a card, its mesh asset path, scale and yaw, from `Docs/PropArt/manifest.json` (T43 recorded the fit). A prop with no model yet falls back to today's shape parts or a plain clay shape.
  2. **`BP_Prop`:** add a static mesh component, `Model`, and a `SetProp(Name)` that loads the mesh from `props.json` (a soft reference, loaded at Scene Prep), sets its scale and yaw, and hides the old shape parts. Keep `PropName`, the grab, throw and give behavior and the table reset.
  3. **Four props on the table:** keep four `BP_Prop` actors on the Prop Table and remove the other four from `L_Stage` (re-place, don't edit templates; see the T17 findings in [T17.md](T17.md)).
  4. **At Scene Prep:** `BP_Show` writes the card's props into the state's `set.props`, and `BP_StageDirector` (`ResetStage`) dresses the four actors with `SetProp`. `FindProp` keeps working by name. Then drop `set.props` from `scenes.json` and from `check_prompts.py`'s set check.
  5. **Check:** two free autoplay shows reach `NHOS: SHOW END`, with `NHOS: ACT` lines that grab and throw the new props; a screenshot of the prop table in each scene, each with a different card's props.
- **Done when:** the check passes, and Claude's screenshots of one free show in a game window show the props change between scenes.
- **Result:** done on 2026-11-15, in two parts. The Mac built `props.json`, `BP_Prop` (`Model`, `LoadProps`, `SetProp`), `BP_StageDirector` (`CardFromShow`, and `ResetStage` dresses the four props) and four props in `L_Stage`; the PC's chain added one `Set Field` node in `BP_Show.StagePrep`, so the state's `set.props` is the card's props, took the `set.props` read out of `BP_Show.LoadData`, and dropped `set.props` from `scenes.json` and the checker. ### Unreal MCP and editor rules found in this task

- **Reloading an asset that this editor saved itself breaks its compile.** After T37 pushed `BPC_LLMClient` from this editor, reloading it with `reload_packages` (with `BP_Show`) logged five "Can't connect pins Self and In Client" errors; a `compile_blueprint` cleared them and left it clean and not dirty. Reload only what came in by a pull.
- **Casts are multi-exec nodes in the DSL**: `(bind _mesh (Utilities|Casting|CastToStaticMesh :Object _obj) (:then ...) (:CastFailed ...))`, and the code after them must go inside `:then` (the call ends the flow). The soft-reference load is `(Utilities|LoadAssetBlocking :Asset (Utilities|ToSoftObjectReference (Utilities|MakeSoftObjectPath :PathString <path>)))`; it reads back as `Utilities|LoadAsset_Blocking`.
- **Another Blueprint's variables read as `Class|<BP>|Get<Var> :self <actor>`** (`Class|BPShow|GetCardId`, `Class|BPStageDirector|GetCardProps`), from an `Actor|GetActorOfClass` result.
- `add_struct_variable` takes `/Script/JsonUtilities.JsonObjectWrapper`, not `/Script/JsonBlueprintUtilities...`.
- `Tools/dslpp.py` needs a `;;; GRAPH <Name>` line before each graph, or it writes an empty file (`Saved/T45/pp.sh` adds it).
- The status bar's console box was ref `tb1` this session (T46's `py "<file>.py"` way).
