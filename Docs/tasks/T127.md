# T127 The web, part 5: the game's files and modes in a browser

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** T112 found that a browser has no real file system for what the game keeps in `Local/` and next to the pak:
  - it reads the loose `Content/NHOS/Data/*.json` that a build stages next to the pak;
  - it writes `Local/progress.json` (the stagehand's first-show flag, T61) and `Local/llm_key.json` (the key screen's keys), and reads `Local/switches.json`;
  - `SG_Player` (a SaveGame, slot `player`, T68) holds the analytics player id and the Play stats setting, whose button T118 hides.

  And "Use my own API keys" can't work well in a browser: each provider would have to allow browser calls, and the keys would sit in the page's storage. T123 says how files and saves behave in the web build.
- **Steps:**
  1. **Read first.** T123's findings on files, saves and reloads; T120's file (where the Mac game keeps `Local/`, which this task builds on); T61's (the first-show flag), T68's (`SG_Player`, the analytics id), T93's (the title's three modes) and T124's (the relay from a browser).
  2. **The data JSON.** Make the web build read `Content/NHOS/Data/*.json` wherever the web platform can (inside the package, or staged where its file system has them). Desktop builds keep the loose files, so they can still change without a new package.
  3. **What must survive a reload.** The first-show flag and `SG_Player` survive a page reload on the web: in a SaveGame, or wherever T123 found that saves last. Desktop keeps `Local/progress.json`, as T120 leaves it.
  4. **Modes.** On the web, the title shows Play and Test for Free, without "Use my own API keys", and the game ignores `Local/switches.json`. Desktop is unchanged.
  5. **Check it** in the web build in Chrome (with T124's relay): a free show and a Play show to the end screen; a reload keeps the first-show flag and the analytics player id (`NHOS: ANALYTICS player <id>` stays the same). On desktop, PIE and a game window behave as before, and a free autoplay show reaches `NHOS: SHOW END`.
- **Done when:** both shows play in Chrome; a reload keeps the first-show flag and the player id; the web title has no own-keys button; desktop is unchanged and a free autoplay show reaches `NHOS: SHOW END`; the design doc's UI section notes the web title, after my OK.
