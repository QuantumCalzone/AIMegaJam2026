# T64 The action builder, the preview line and Action!

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** the input spec in [T62.md](T62.md) ("The input spec": rows 1 and 2 of "Layout", "Building an action" and "Submitting"). I build my action by clicks, so I never type a place, a prop or a stage direction, and I can only build what the game would accept from an AI.
- **Steps:**
  1. **A new widget, `WBP_ActionBuilder`,** in `Content/NHOS/UI/`, with a chip widget (`WBP_Chip`) if it needs one. Style both from `UIStyle` and T32's shared pieces. It sits in `WBP_Stage`'s input row above the input box, with the preview line above it (the spec's "Layout"). Keep the logic in the widget, and have `BP_Show` reach it through as few nodes as it can (the build note "New systems get their own Blueprint").
  2. **The action buttons:** Move, Look, Grab, Throw, Give, Look around and No action. No action is picked at the start of each of my scene turns. Picking another action clears the chips I picked.
  3. **The chips:** only the picked action's valid choices show, from T62's `ItemsFor` and `TargetsFor`, read at the start of each turn and after each pick.
     - Throw and Give show the props I hold first, then their targets once I pick a prop.
     - Clicking a picked chip again unpicks it, and the chips after it.
     - Actors show by the names on my screen (`SeatLabel`, such as "Meta"), in their colors. The builder keeps their Player names for the call.
     - Look around and No action have no chips.
  4. **Greyed actions:** an action with no valid choice is greyed, with a tip on hover. Throw and Give when I hold nothing: "Grab something first." Grab when every prop is held: "Nothing free to grab."
  5. **Focus never moves.** No button or chip takes keyboard focus (`IsFocusable` off), so what I type stays in the input box while I click. T34's file says to keep it that way.
  6. **The preview line,** in a terminal style (a mono font from `UIStyle`; add one there if it has none), shows the action as built and the typed line, live: `throw rose at @Meta: "Oops, my servo slipped."` An unfinished action shows what's missing, such as `throw rose at ...`. Pick how No action with an empty line reads (for example `stand still`), and write it under "## Findings".
  7. **Action!** A button at the right end of the input row, and Enter in the input box, send my turn through T63's `SendHumanTurn(Verb, Item, Target, Line)`. While a picked action still lacks a chip, Action! is greyed with the tip "Pick a target first." and Enter does nothing; only T66's timer sends an unfinished action. No action with an empty line is allowed: I just stand there. After I send, the builder and Action! are disabled until my next turn.
  8. **Only in scene turns.** The builder and the preview line show only in my scene turns. T66 does the other phases.
  9. **The hints follow.** If the input box's hint or the turn line (`SetPrompt`) still tells me to type what I do, change it to point at the builder.
- **Done when:**
  - In PIE (Test for Free, autoplay off, a 1600 × 900 window), screenshots show: the builder at a turn's start with No action picked and Throw and Give greyed, and the tip on hover; Grab with its chips; a picked chip with its preview line and some typed text; the next turn, Throw with the held prop and then its targets.
  - Sending a grab prints `NHOS: HUMAN grab <prop> - says=...`, my robot grabs the prop, and the chat shows my line. The throw on the next turn plays too.
  - Typing, clicking Grab and typing on puts every letter in the input box.
  - A free autoplay show in a game window reaches `NHOS: SHOW END` with no `LogScript` line.
  - Under "## Findings", Claude says from the screenshots whether a first-time player could build a turn without help, as a critical first-time player would.
