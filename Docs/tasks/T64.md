- **Steps:**
  1. **A new widget, `WBP_ActionBuilder`,** in `Content/NHOS/UI/`, with a chip widget (`WBP_Chip`) if it needs one. Style both from `UIStyle` and T32's shared pieces.   2. **The action buttons:** Move, Look, Grab, Throw, Give, Look around and No action. No action is picked at the start of each of my scene turns. Picking another action clears the chips I picked.

  6. **The preview line,** in a terminal style (a mono font from `UIStyle`; add one there if it has none), shows the action as built and the typed line, live: `throw rose at @Meta: "Oops, my servo slipped."` An unfinished action shows what's missing, such as `throw rose at ...`. While a picked action still lacks a chip, Action! is greyed with the tip "Pick a target first." and Enter does nothing; only T66's timer sends an unfinished action. No action with an empty line is allowed: I just stand there. After I send, the builder and Action! are disabled until my next turn.
  8. **Only in scene turns.** The builder and the preview line show only in my scene turns. T66 does the other phases.
  9. **The hints follow.** If the input box's hint or the turn line (`SetPrompt`) still tells me to type what I do, change it to point at the builder.

**How it differs from the sheet:**
1. **The function `PreviewText` is called `MakePreview`,** because the TextBlock `PreviewText` is a widget variable with the same name.
2. **`Arm`'s input is `ForSeat`,** and the outputs of `GetAction` and `Seal` are `SendVerb`, `SendItem`, `SendTarget` and `Ready`. The sheet's `Seat`, `Verb`, `Item` and `Target` are also member variables of the builder. Callers bind the outputs by position, as the sheet's `TakeAction` does, so only the names differ.
3. **The mono font is a variable on the widget, `MonoFont`** (SlateFontInfo, default `/Engine/EngineFonts/DroidSansMono` at size 18, typeface `Default`). `StyleAll` sets the preview line's font from it. `UIStyle`'s "Mono" role stays for the chain (see the list below). **The engine font's one typeface is named `Default`, not `Regular`** (sheet survey 8). Its `fontCacheType` is `Runtime`. So `UIFont`'s "Mono" branch needs `:TypefaceFontName "Default"`.
4. **New: `SetFocusBack(Target)` and `KeepFocus()`.** With every button and chip `IsFocusable` off, a click on Grab still took the keyboard focus away from the input box in PIE. On a mouse-down that sets no focus, Slate gives the focus to the nearest focusable widget under the cursor, here the game viewport. Now `PickVerb` and `ChipClicked` end with `KeepFocus`, which gives the focus back to the widget that `SetFocusBack` named. The chain must call `SetFocusBack` once with `WBP_Stage`'s `InputBox` (below). After that, the PIE snapshot showed the input box still `[focused]` after a click on Grab and after a click on a chip.
5. **`WhyNot` takes each list's length right after its call** (`_ic`, `_tc`, `_hc`), so a later call to the director can't change a list it still reads.
6. **`OpenTurn` prints `seat=?` instead of reading past the end** when the seat isn't in `BP_Show.SeatId`.
7. **The node names that differ from the sheet:** `Panel|AddChildtoWrapBox` (not `Widget|AddChildToWrapBox`) and `Widget|Panel|ClearChildren` (not `Widget|ClearChildren`).
8. **The chip's seat bar is a 14 × 20 swatch, not 6 px wide.** In the first shots, the 6-unit bar with its 2 px ink outline on each side showed almost no color. At 14 wide the four seat colors read clearly, on plum and on paper.

**Unreal MCP rules found in this part:**
