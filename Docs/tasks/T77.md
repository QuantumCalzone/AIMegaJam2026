# T77 Each robot shows its emotion as its line plays, mine too

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** T75 taught each robot to act out an emotion, and T76 made every AI reply carry one. This task plays it: when a line plays, its robot shows the emotion, as the line starts to type out (T73). My robot must emote too, or a robot that never shows an emotion gives me away. My call (2026-11-15): the input LLM picks my emotion from my line, and T78 lets me pick it myself. The AIs can't see the stage, so the shared log tells them what each face shows.
- **Steps:**
  1. **The design doc first.** After my OK, change the input LLM's prompt (step 6) and the description of the shared log (step 5) in the doc's Bot Prompts tab. Then copy them word for word into `prompts.json`. Check that the Rules tab's emotion section from T76 still matches what this task builds.
  2. **Free replies in the game.** `BPC_LLMClient.FreeReply` fills `emotion` from each phase's `emotions` list in `free_mode.json`, as the relay does since T76. For my line, `free_mode.json` gets a small keyword table, in a form both the game and the relay read. For example: "sorry" means embarrassed, a question mark means confused, "you" with "lying" means suspicious, and an exclamation mark means surprised. Anything else is `neutral`. The relay's input phase uses the same table.
  3. **Keep it with the line.** `HandleReply` keeps each reply's emotion on the line's entry, so it reaches `BPC_LinePlayer` with the line. An empty or unknown id becomes `neutral`.
  4. **Show it when the line plays.** When `BPC_LinePlayer.PlayCur` plays a line (where the robot lights up and `StageLine` runs), the seat's robot gets `Emote(Emotion)`. That covers every line that plays: scene turns, Free Talk, a pass (the robot says nothing but shows its face, beside T57's "passed" marker), T58's last word, reactions and closing lines. A vote shows the voter's emotion when its vote is read out, if the votes play one by one; if they don't, a vote's emotion is ignored. Write which under "## Findings".
  5. **The shared log.** Each log entry gets `feels`: the emotion's `word` from `emotes.json`, left out for `neutral`. Every actor gets it, human or AI, so the AIs read the faces the audience sees. Update the line in `prompts.json` `_readme` that lists the log's fields, and the `game` prompt if it describes the log. The log still never holds my raw input, times, errors or notes.
  6. **My emotion.** The input LLM picks it in the call that already fixes my spelling (T63's call). `prompts.json` `input` and `asks.input` tell it to pick the emotion my line shows, and `neutral` when it can't tell. The reply's `emotion` becomes my emotion; its other fields stay ignored, as T63 left them.
     - If that call is skipped, fails or comes back late, my typed line goes through the keyword table from step 2 instead, with no call.
     - If I say nothing (No action with an empty line, or a pass), my emotion is `neutral`.
     - Print `NHOS: HUMAN emotion=<id> from=<llm|keywords|none>`.
     - Autoplay's canned lines take the same path, so they get emotions the same way.
  7. **The checker.** `Tools/check_prompts.py` checks the keyword table (every emotion is a known id). Its input cases check that the input reply's emotion is a known id, and they warn (not fail) when a line with a clear emotion (an apology, an accusation, a question) gets one that doesn't fit.
