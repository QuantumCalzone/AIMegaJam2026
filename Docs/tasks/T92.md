# T92 The Mac builds and pushes the post-jam Mac file on each merge into main

Back to [the plan](../Plan.md). This task's title line, **Model and effort**, **Depends on**, **Needs**, **Touches** and any **Waiting:** or **Blocked:** line are in its entry there, under "Open".

## Task

- **Why:** my request on 2026-11-15: each merge into `main` builds the game on the PC and on the Mac, and butler pushes both builds to the itch.io page as post-jam files. T89 built the Windows half, and T91 made a merge into `main` the trigger. This task adds the Mac: the Mac becomes a second self-hosted runner, packages the same commit as the PC, and pushes it to a new channel, `mac-postjam`. The PC can't do this job, because a Mac build needs Xcode, which runs only on a Mac.
- **What stays the same:**
  - The jam's files on the page never change. If the page has a jam Mac file, it stays as it is, like the jam's Windows file.
  - Every post-jam download says it is post-jam: the label, the downloaded file name and the folder inside.
  - The secrets check gates every push.
  - The PC's job doesn't change.
- **Steps:**
  1. **Read first.**
     - T89's and T91's files, above all T89's findings on what this task needs (T89 step 11).
     - "Package a macOS build" in `CLAUDE.md`. It has three traps:
       - The archive step copies the wrong app. The playable app is `Saved/StagedBuilds/Mac/AIMegaJam2026.app`.
       - The app is sandboxed and reads `Local/` from inside the bundle.
       - Only `ditto -c -k --norsrc --noextattr --keepParent` makes a zip that keeps the signature.
     - butler's pages on pushing and installing, and what itch.io says about Mac `.app` builds.
     - The page's current uploads.
  2. **Install butler on the Mac.** Ask my OK first. Download butler from broth. Check broth's channels for a darwin build, and use an arm64 one if broth has it. Put butler outside the repo and on PATH, and check it with `butler version`. On the runner, butler reads the same `BUTLER_API_KEY` Actions secret as the PC's runner. If you need a `butler login` by hand, I run it myself.
  3. **A deploy worktree on the Mac.** Make one worktree of the Mac's repo folder, for example `~/Projects/NHOS_deploy`. Each run moves it to its commit (`git fetch`, `git checkout --detach <sha>`, `git lfs pull`), as T89 does on the PC. It shares the repo folder's `.git/lfs`, so a run downloads only new LFS objects. Never build in the repo folder, where sessions have uncommitted work.
  4. **The Mac path in `Tools/deploy_itch.py`** (its platform comes from the OS, or from `--platform mac`):
     - Package the commit with the macOS command in `CLAUDE.md`, into a new folder per run.
     - Copy `Saved/StagedBuilds/Mac/AIMegaJam2026.app` from the deploy worktree with `ditto` into a folder named `NoHumansOnSet_PostJam_Mac`.
     - A fresh build should have no `Local/` and no `Saved/` in the bundle. Leave out any `.dSYM`. If something inside the bundle has to change, sign the bundle again with an ad hoc signature (`codesign --force --deep --sign -`), because any change inside a signed bundle breaks its signature.
     - Run `codesign --verify --deep --strict` on the app. Then run `Tools/check_build_secrets.py --local <the Mac's repo folder>/Local` on the build. Push only when both pass. As on the PC, exit code 2 also stops the push, and so does a check that found no key files.
     - Push with `butler push <build> quantumcalzone/no-humans-on-set:mac-postjam --userversion <the same form as the PC's> --if-changed`. Both files then carry the version of the same merge commit. The word "mac" in the channel name tags the file as macOS. Before the first push, read the channel back and confirm it isn't a jam file's channel.
     - Find out which push keeps the app's signature after a player downloads it in a browser: a push of the folder, or a push of the `ditto` zip. Use the one that keeps it, and write down why.
  5. **The first push, hidden.** Run the script by hand with `--hidden`. Make the page label say post-jam, for example "No Humans On Set (post-jam build, Mac)". Make sure the downloaded file has "PostJam" in its name. The rest is as in T89 step 8. Make the file visible only on my OK.
  6. **The runner.** Ask my OK before you download the GitHub Actions runner and register the Mac. Put it outside the repo, for example `~/actions-runner`, with the labels `self-hosted, macOS, nhos-build`. Run it as my user, as a launchd service (`./svc.sh install`), so it sees the engine, Xcode, Python 3, git-lfs and butler. A job waits in the queue while the Mac sleeps or is offline. Find out how long GitHub keeps a queued job, and write the answer in `CLAUDE.md`.
  7. **The workflow.** Add a Mac job with the same trigger as T91's: pushes to `main` with T89's `paths`, plus `workflow_dispatch`, and the itch.io push only on `refs/heads/main`. Either add the job to T89's workflow or put it in its own file, `.github/workflows/itch-mac.yml`. Give it `runs-on: [self-hosted, macOS, nhos-build]` and its own concurrency group, `itch-mac`, so the two machines build at the same time and a failure on one doesn't stop the other.
  8. **The docs.**
     - `CLAUDE.md`, under "Package a macOS build": the deploy, how to run the script by hand on the Mac, and the post-jam zip name that T89 set, `QuantumCalzone_NoHumansOnSet_PostJam_Mac_<YYYY-MM-DD>.zip`.
     - `README.md`: the same.
     - `Docs/ItchPage.md`: the Uploads row.
- **Done when:**
  1. `Tools/deploy_itch.py --dry-run` on the Mac packages `main`'s tip in the deploy worktree. The build has a `NoHumansOnSet_PostJam_Mac` folder with the app inside, `codesign --verify --deep --strict` passes, and the secrets check ends with exit code 0.
  2. A key-shaped string planted in a copy of the build makes the script stop at the secrets check, and nothing is pushed (`--build <copy> --dry-run`).
  3. After the hidden push and my OK to show the file, a signed-out visitor sees the post-jam Mac label, and the file they download has "PostJam" in its name. Unzipped with Archive Utility, the app passes `codesign --verify --deep --strict`. A copy of it plays a free autoplay show to `NHOS: SHOW END`. For that run, put `{"analytics": "off", "mode": "free", "autoplay": true}` in the copy's `Contents/UE/AIMegaJam2026/Local/switches.json`, sign the copy ad hoc again, and open it once with Open Anyway. Delete the copy afterwards.
  4. The page shows the jam's files first, with the same names, sizes and dates as before.
  5. The next release (a merge into `main`, on my word) runs both jobs. `windows-postjam` and `mac-postjam` both show the merge commit's version.
  6. No key is in git, in the workflow files, in the job logs or in this chat.
