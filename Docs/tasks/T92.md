## Findings

All on the Mac (M2 Max, macOS 27.2, Xcode 27.2, UE 5.8.4), 2026-11-19 local time, 2026-11-20 UTC. The answers to the build sheet's open questions Q1 to Q11 are marked.

### The code

- **M1 to M7 went in as the build sheet wrote them,** fitted to T91's code: `shlex` quoting in the `.command` file (M1); a Mac default deploy worktree, `~/Projects/NHOS_deploy` (M2, M3); `stop_leftovers` reads `comm` and `args` apart at full width, with `clang++` and `ld` added (M4); `ditto --clone` and the archive's useless app deleted (M5); `strip_build` says whether it changed the `.app`, and `resign_app` signs it again with `--preserve-metadata=identifier,entitlements,requirements,flags,runtime` and stops if the entitlements change (M6); `verify_signature` gates the push after the secrets check (M7).
- **One more change: the Mac `.command` ends with "Press Return to close this window."** Terminal's profile here ("Clear Dark") doesn't set "When the shell exits", and Terminal may close a window whose script ended cleanly, so the result could vanish. The Windows console already ends with `pause`. After the "Dry run of dev" run, the `/bin/sh .../DeployItch.command` process was still waiting for Return (Q7).
- **The re-sign path was tested on a copy:** a `Local/switches.json` written into the bundle broke the seal ("a sealed resource is missing or invalid"); the run deleted that `Local/`, signed the app again, kept all four entitlements, and the gate passed. The main binary is not linker-signed (`flags=0x2(adhoc)`), so `--preserve-metadata` works (Q6).

### The runs

- **The first dry run by hand** (`deploy_itch.py --dry-run`, the engine's Python, `origin/main` = `10f8540`): it made the deploy worktree, `git lfs pull` worked with git-lfs 3.0.2 under Rosetta (Q10), and `BuildCookRun` took 114 s, with the shared DDC warm (Q8). The staged app passes `codesign --verify --deep --strict` straight out of staging, so normally nothing is signed again (Q5). Secrets check: clean, with the Mac `.pak` and `.utoc` opened by the Mac UnrealPak (1732 and 2278 files read; `global.utoc` has no file index and its raw bytes were checked).
- **What is in the staged app (Q4):** 1.2 GB, 45 files, **no symlinks** (the `libtbb` versions are plain copies), no `.dSYM`, no `.pem`, no `Local/`. Its entitlements: `app-sandbox`, `get-task-allow`, `network.client`, `network.server`. Its only extended attribute is `com.apple.provenance`. Its executable files are the Mach-O binaries plus `Engine/Extras/GPUDumpViewer/OpenGPUDumpViewer.sh` and `.bat`.
- **Disk (Q8):** the deploy worktree is 7.3 GB after two packages; 46 GiB were free before the task and 39 GiB after.

### Step 5: the folder keeps the signature (Q1, Q2)

- **Pushing the folder works, so the script stays as it is (option A).** After I showed the file, a signed-out browser saw "no-humans-on-set-mac.zip 760 MB Version 2026-11-20-10f8540", marked macOS, and the page now says "A downloadable game for Windows and macOS". The download (797,776,552 bytes) was quarantined. Its zip stores Unix modes (`-rwxr-xr-x` on the main binary). Archive Utility unzipped it with no `._` files, and the app passes `codesign --verify --deep --strict --verbose=2` ("valid on disk", "satisfies its Designated Requirement") with its four entitlements. `spctl` rejects it, as it does any app that isn't notarized.
- **Why it keeps:** the app has no symlinks, its signature lives in its files (`_CodeSignature/CodeResources` and the Mach-O binaries) rather than in extended attributes a zip would drop, and `--fix-permissions` sets the exec bit on the Mach-O files. Option B (a pushed `ditto` zip with `--no-auto-unzip`) wasn't needed, so Q2 stays open.

### Found on the way, for other tasks

- **Three glow materials fall back to the default material, on every platform.** The cook of `10f8540` warns: "Failed to compile Material for platform SF_METAL_SM6, Default Material will be used in game", with "(Node TextureSample) Sampler type is Grayscale, should be Linear Grayscale" for `T_GlowStickSword_Glow`, `T_GlowingBriefcase_Glow` and `T_GlowingStaff_Glow` (materials `M_GlowStickSword`, `M_GlowingBriefcase`, `M_GlowingStaff` under `Content/NHOS/Stage/Props/`, T105). The packaged Mac game logs the same for the glow-stick sword. That check doesn't depend on the platform, so the Windows build almost certainly shows the same three props with the default material. The fix is the samplers' type (or the textures' sRGB) in the editor.
- **The Mac app can't keep what it writes into its bundle (Q11, in part).** macOS ran the downloaded app from `/private/var/folders/.../AppTranslocation/.../d/AIMegaJam2026.app`, a randomized read-only copy, as it does for any quarantined app that the player hasn't moved. So the key screen's `Local/llm_key.json` and the stagehand's `Local/progress.json` can't be saved there, and the sandbox may block a moved app too. Autoplay turns the tips off, so this run never tried to save `progress.json`: untested. A fix would write those files in a folder the sandbox allows (the app's container) on a Mac.
