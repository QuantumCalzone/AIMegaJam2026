## Task

- **Why:** my request on 2026-11-15: each release goes to the itch.io page as a Windows and a Mac file. Rewritten on 2026-11-17: T89 dropped GitHub Actions for an editor menu, and builds no longer say post-jam. T89 already wrote the Mac path in `Tools/deploy_itch.py` and the Mac side of the menu (`Content/Python/nhos_itch_deploy.py` opens Terminal through `Saved/DeployItch.command`), but none of it has run on a Mac yet. This task runs it on the Mac, fixes what doesn't work, and makes the first push to the `mac` channel. The PC can't do it, because a Mac build needs Xcode.
- **What stays the same:** the jam's file never changes; the secrets check gates every push; the PC's path doesn't change.
- **Steps:**
  1. **Read first.** T89's file (all three parts; part 2 lists what the Mac needs) and T91's (after it, the menu builds `main`'s tip). "Package a macOS build" in `CLAUDE.md`, with its three traps: the archive step copies the wrong app (the playable one is `Saved/StagedBuilds/Mac/AIMegaJam2026.app`), the app is sandboxed and reads `Local/` from inside the bundle, and only `ditto -c -k --norsrc --noextattr --keepParent` makes a zip that keeps the signature. butler's pages on pushing and on Mac `.app` builds.
  2. **butler on the Mac.** Use the itch app's copy (`~/Library/Application Support/itch/broth/butler/`) if it has one; otherwise ask my OK to download a darwin arm64 build from broth. I run `butler login` myself.
  3. **The deploy worktree.** One worktree of the Mac's repo folder, for example `~/Projects/NHOS_deploy`. Make the menu find it: a Mac default in `deploy_itch.py` (the PC's default is `C:/Users/Personal/Projects/NHOS_deploy`), or an `NHOS_DEPLOY` that the editor's environment sees.
  4. **Run the Mac path and fix it.** `deploy_itch.py --dry-run` on the Mac: package, copy the staged app with `ditto` into `NoHumansOnSet_Mac/`, strip `Local/` and `Saved/` (if anything inside the bundle has to change, sign it again ad hoc with `codesign --force --deep --sign -`), then the secrets check with `--local <the Mac's repo folder>/Local`. Add a `codesign --verify --deep --strict` gate before the push. Check the menu entries in the Mac editor: Terminal opens and runs the script, and the log lands in `Saved/Logs/DeployItch.log`.
  5. **Which push keeps the signature.** Find out whether pushing the folder (with `--fix-permissions`, as the script does now) or pushing the `ditto` zip keeps the app's signature after a player downloads it in a browser. Use the one that keeps it, and write down why.
  6. **The first push, hidden.** `deploy_itch.py --hidden` makes the `mac` channel (the menu never makes a channel). itch names a channel's file `<game slug>-<channel>.zip` (T89), so the file should be `no-humans-on-set-mac.zip`. Show it on the page's edit screen only on my OK (untick "Hide this file" and save).
  7. **The docs.** `CLAUDE.md` ("Package a macOS build" and "Deploys to itch.io": the Mac menu path, the deploy worktree, `codesign`), `README.md`, and `Docs/ItchPage.md` (the Uploads row).
- **Done when:**
  1. Tools > itch.io > "Build only (dry run)" in the Mac editor packages the tip in the deploy worktree: a `NoHumansOnSet_Mac` folder with the app inside, `codesign --verify --deep --strict` passes, and the secrets check ends with exit code 0.
  2. A key-shaped string planted in a copy of the build makes the script stop at the secrets check, and nothing is pushed (`--build <copy> --dry-run`).
  3. After the hidden push and my OK to show the file, a signed-out visitor can download `no-humans-on-set-mac.zip`. Unzipped with Archive Utility, the app passes `codesign --verify --deep --strict`. A copy of it plays a free autoplay show to `NHOS: SHOW END` (with `{"analytics": "off", "mode": "free", "autoplay": true}` in the copy's `Contents/UE/AIMegaJam2026/Local/switches.json`, signed ad hoc again, opened once with Open Anyway). Delete the copy afterwards.
  4. The jam's file is unchanged.
  5. No key is in git or in this chat.
