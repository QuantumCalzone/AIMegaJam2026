- **Depends on:** T75 (the ids in `emotes.json`), T69 (the reply shape, the prompts, `free_mode.json` and the relay as T58 to T69 leave them)

- **Touches:** `Content/NHOS/Data/llm.json` (`reply_schema`, `_readme`), `Content/NHOS/Data/prompts.json` (`base`, `_readme`), `Content/NHOS/Data/free_mode.json` (`emotions` per phase, `_readme`), `Relay/src/index.js`, `Relay/test/curl-tests.sh`, `Relay/README.md`, `Tools/check_prompts.py`, the design doc, `Docs/tasks/T76.md`.
- **Why:** the AI players should choose the emotion their robot shows (see [T75.md](T75.md), "Why"). The LLM sends it back with every reply, in the one reply shape, and the game plays it on the robot (T77). This task is the data half: the reply shape, the prompt that asks for it, free mode in the relay, and the checker. It needs no editor. The game reads no new field until T77, so it keeps running as it is.
- **Steps:**
  1. **The design doc first.** Put the whole emotion feature (T75 to T78) in the design doc once, after my OK: in the Rules tab, every robot shows an emotion while its line plays, everyone on stage sees every face, the AIs read the faces in the shared log (T77), and my robot's emotion is picked from my line unless I pick it myself (T77, T78). In the Bot Prompts tab, the new rule line from step 3. Then copy that line word for word into `prompts.json`.
  2. **The reply shape.** `llm.json` `reply_schema` gets `emotion`: a string whose `enum` is the ids in `Content/NHOS/Data/emotes.json` (T75). Make it required, like every other field, because the four providers' strict schemas need every field required. Every ask gets it back, the input ask too: T77 uses that one for my emotion. Update the lines in `llm.json` `_readme` and `prompts.json` `_readme` that list the reply's fields.
  3. **The prompt.** One rule line in `base`, which every bot reads. Each reply picks the emotion its robot shows while its line plays. It is the emotion the bot acts, which isn't always what it feels: a bot that suspects someone may act calm, and a bot under suspicion may fake confusion. Use `neutral` when nothing moves you, but don't stick to one. A pass still shows its emotion: you say nothing, but you can look worried. The emotion never goes into the speech as a tag or a stage direction (the legibility rule).
  4. **Free mode in the relay.** In `free_mode.json`, each phase gets a weighted `emotions` list, in the same form as `scene_actions`. For example, scene lines lean neutral, happy and confused; Free Talk leans suspicious and worried; votes lean suspicious and smug; reactions lean surprised, sad and smug. The input phase gets none (T77 adds my keyword table). The relay's free reply (`freeReply` in `Relay/src/index.js`) fills `emotion` from the phase's list, or `neutral` when the phase has none. Update the `_readme`. The game's own free mode (`BPC_LLMClient.FreeReply`) reads the lists in T77.
  5. **The checker.** `Tools/check_prompts.py` checks that:
     - the enum in `reply_schema` holds exactly the ids in `emotes.json`, in any order;
     - each emotion in `free_mode.json` is a known id;
     - in a live run, each reply's emotion is a known id (the schema should force it, but check, because a provider may not enforce `enum`).
     It also prints how often each provider picked each emotion, so a bot stuck on one emotion, or always `neutral`, shows.
  6. **The relay's tests.** `bash Relay/test/curl-tests.sh <relay address>` still passes, and a free reply carries an emotion. If `Relay/README.md` lists the reply's fields, add `emotion`.
