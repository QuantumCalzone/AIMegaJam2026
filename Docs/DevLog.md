# Dev log

One line for each commit that changes the game or the plan, oldest first. The jam's Glass Box category needs a dev log, and it must be submitted with the entry; it can't be added later.

Format: `- <date and time, UTC> · <task ID, or Plan> · <model and effort> · <what was done and what was learned>`

- 2026-11-13 23:20 UTC · Plan · Claude Fable 5.2 · Read the design doc and saved a copy in the repo. Checked the engine install: it ships HTTP and JSON Blueprint plugins, both off by default, so a Blueprint-only LLM call looks possible. Wrote the MVP plan: 14 tasks, the LLM-call spike first, a playtest gate at T11, and task claims through Git LFS locks.
- 2026-11-13 23:49 UTC · T01 · Claude Opus 5.5 (high) · One Claude call from Blueprint works in PIE: BPC_LLMClient builds the request with JSON nodes, sends it with the HttpBlueprint node and parses a JSON reply ("NHOS: SPIKE OK"); a wrong key gives the API error ("NHOS: SPIKE FAIL"). About 2 s per call. Built through Unreal MCP graph scripts; the Http Request node needed hand wiring, and the level had to be made in the editor.
- 2026-11-14 00:12 UTC · T02 · Claude Opus 5.5 (high) · The Claude call works in a packaged Windows Development build too ("NHOS: SPIKE OK", 1.5-1.8 s per call), so LLM calls stay Blueprint-only. But the HTTP and JSON plugins make the packager compile a game program, so packaging needs Visual Studio C++ and the Windows 11 SDK, plus -nocompileeditor -unrealexe to skip a project editor build. Data files ship loose next to the pak; the key goes in the build's Local/ folder and must never be zipped. Build: 968 MB, 387 MB zipped without the .pdb.
- 2026-11-14 00:15 UTC · Plan · Claude Opus 5.5 · Every Claude role (actor, input LLM, Director) now runs claude-haiku-5-5 at low effort, the cheapest model at its lowest level, to cut cost per call about 40x from Opus 5.5. Haiku 5.5 has no server-side fallback, so fallbacks are off in llm.json. Not yet checked in PIE.
- 2026-11-14 00:35 UTC · T03 · Claude Opus 5.5 (high) · Wrote the game's prompts and data: the opening game prompt, the base prompt and four personas (word for word from the design), the input LLM and Director prompts, one ask per request kind, the café set with 2 scene cards and 6 notes with decoys, and the real reply schema. The user message is a JSON state object. Tools/check_prompts.py sends every ask with the game's request body; all 34 replies pass on claude-haiku-5-5 at low effort, at about 2 s per call and $0.03 per show. Asking for 20 words keeps lines under the 25-word cap, and putting the boolean field last in the schema cut stray characters at the end of reasons from 12% to 3%.
- 2026-11-14 00:52 UTC · T04 · Claude Opus 5.5 (high) · The stage screen: WBP_Stage has a phase header, a scrolling log, and an input box with a Send button; BP_ShowGameMode and BP_ShowPlayerController show it on L_Stage with the cursor on and the focus in the box. Typed lines go straight to the log through AddLogLine, and an OnSend dispatcher is ready for T05. Checked in PIE with no person at the keyboard: Unreal MCP's Slate inspector typed "hello", pressed Enter and took the screenshot. Keeping the focus took two settings: the box keeps focus on commit, and the button can't take focus.
- 2026-11-14 01:21 UTC · T05 · Claude Opus 5.5 (high) · One AI reply on screen: a typed line goes to The Worrier with the real game, base and persona prompts, and its in-character answer shows in the log in about 2 s ("NHOS: LLM worrier-1 ok"). BPC_LLMClient now has Ask(Tag, Role, System, User) and an OnAnswer dispatcher with typed reply fields; each ask gets its own BPC_LLMRequest component, because one shared Http Request node would mix up the tags of asks in flight at once. Two asks sent together came back under their own tags. A missing key shows "AI service unavailable" with the reason; a bad key makes The Worrier look around. Learned: a failed DSL write rolls back and compiles the whole Blueprint, and binding a dispatcher to a function needs hand-made nodes.
